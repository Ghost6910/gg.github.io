แปลและเรียบเรียง Remote Login

Remote login ทำให้ผู้ใช้เข้าถึงบริการคำสั่งบนเครื่องอีกแห่ง สไลด์ยก TELNET ซึ่งจัดรูป terminal ด้วยแนวคิด Network Virtual Terminal การเข้าใจรูปแบบ terminal ช่วยอธิบายว่าทำไมเครื่องต่างระบบยังแลกข้อมูลควบคุมกันได้

TELNET แบบดั้งเดิมส่งข้อมูลโดยไม่ให้การเข้ารหัสแบบ SSH จึงให้แยกการสาธิต protocol ในสไลด์จากการนำไปใช้งานจริง SSH เป็นโปรโตคอลคนละตัว ไม่ใช่เปิดตัวเลือกในข้อความ TELNET แล้วกลายเป็นสิ่งเดียวกัน

กลับสารบัญ ↑

E-mail: ใครส่งและใครดึง

User agent ใช้อ่าน/เขียนอีเมล Mail server มี mailbox และ queue SMTP ใช้ส่งจาก client ที่ยื่นส่งไป server และส่งระหว่าง server ส่วน POP3/IMAP ใช้เข้าถึงกล่องข้อความตามรูปแบบบริการ

SMTP เป็นแนว push คือฝั่งผู้ส่งริเริ่มส่งไปปลายทาง ส่วนการอ่านเมลเป็นอีกขั้น IMAP เก็บสถานะและจัดการกล่องข้อความบน server ได้ละเอียดกว่าแบบการดึงพื้นฐานใน POP3 แต่พฤติกรรมการเก็บ/ลบขึ้นกับโหมด client ด้วย

MIME เพิ่มวิธีอธิบายชนิดเนื้อหา encoding และส่วนแนบเพื่อส่งข้อมูลเกินข้อความพื้นฐาน การ encode เช่น Base64 ไม่ใช่ encryption ผู้ที่อ่านข้อมูลได้ยังถอดกลับได้

กลับสารบัญ ↑

FTP

FTP แบบดั้งเดิมแยก control connection จาก data connection Control โดยทั่วไปใช้ TCP 21 ส่วน data ขึ้นกับ active/passive mode Active ให้ server เริ่ม data connection ไป client; Passive ให้ client เชื่อมไป port ที่ server แจ้ง จึงมีผลเมื่อผ่าน NAT/firewall

คำตอบว่า FTP ใช้ port 20 สำหรับข้อมูลทุกกรณีจึงไม่ครบ ต้องบอก active/passive และบริบท ส่วน SFTP เป็นบริการถ่ายโอนผ่าน SSH และ FTPS คือ FTP ที่ใช้ TLS เป็นคนละระบบ

กลับสารบัญ ↑

ตารางทบทวนพอร์ตตามแบบเรียน

บริการค่าที่มักใช้ในโจทย์พื้นฐานความหมาย
TELNETTCP 23remote terminal แบบดั้งเดิม
SSHTCP 22remote access ที่มีการปกป้องด้วยโปรโตคอล SSH
SMTPTCP 25server-to-server mail transfer ในแบบพื้นฐาน
POP3TCP 110เข้าถึงกล่องเมลแบบ POP3 พื้นฐาน
IMAPTCP 143เข้าถึงกล่องเมลแบบ IMAP พื้นฐาน
FTP controlTCP 21ช่องคำสั่ง FTP

ตารางนี้สำหรับจำโปรโตคอลในโจทย์ ไม่ใช่รายชื่อโหมด TLS หรือ submission ครบทุกกรณี หมายเลข port ใช้ค่าอื่นได้เมื่อมีการตั้งระบบให้ตรงกัน

ลองตอบ: ส่งเมลถึง server แล้วอ่านเมลใช้ SMTP ตัวเดียวเสมอหรือไม่

เฉลยและเหตุผล: ไม่ SMTP เน้นส่ง ส่วน POP3/IMAP ใช้เข้าถึง mailbox เว็บเมลยังอาจใช้ HTTP(S) ระหว่างเบราว์เซอร์กับบริการเว็บ

ลองตอบ: Base64 ทำให้ไฟล์แนบเป็นความลับหรือไม่

เฉลยและเหตุผล: ไม่ เป็นการเข้ารหัสรูปแบบเพื่อขนส่ง ไม่ใช่การเข้ารหัสลับด้วยกุญแจ

จำให้ได้: แยก SMTP/POP3/IMAP, control/data ของ FTP และแยก encoding จาก encryption

Figure 26.4 shows an example of option negotiation. In this example, the client wants the server to echo each character sent to the server. The echo option is enabled by the server because it is the server that sends the characters back to the user terminal. Therefore, the client should request from the server the enabling of the option using DO. The request consists of three characters: IAC, DO, and ECHO. The server accepts the request and enables the option. It informs the client by sending the three-character approval: IAC, WILL, and ECHO.
