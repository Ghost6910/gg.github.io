แปลและเรียบเรียงบริการ IP

IP ส่ง packet แบบ connectionless และ best-effort ไม่มีการรับประกันว่าถึง ครบ เรียง หรือไม่มีซ้ำด้วยตัว IP เอง ความน่าเชื่อถืออาจถูกเพิ่มโดย transport หรือ application แยก routing หาเส้นทางออกจาก forwarding เลือกขาออกให้ packet หนึ่งตัว

IPv4 header มีข้อมูลเช่น version, header length, total length, identification, flags, fragment offset, TTL, protocol, header checksum และ source/destination IP ค่า protocol ระบุชนิดข้อมูลชั้นบน ไม่ใช่ TCP/UDP port

Fragmentation แบบละเอียด

MTU เป็นขนาด packet ชั้นที่กำหนดซึ่งลิงก์รองรับ หาก IPv4 datagram ใหญ่เกินและอนุญาต fragmentation อาจแบ่งเป็น fragments โดยแต่ละ fragment มี IP header ของตนเอง และนำไปประกอบกลับที่ปลายทาง

ตัวอย่าง IPv4 total length 4,000 bytes, header 20, MTU 1,500: payload เดิม 3,980; แต่ละชิ้นที่ไม่ใช่สุดท้ายบรรทุกได้ 1,480 ซึ่งหาร 8 ลงตัว ได้ชิ้น payload 1,480, 1,480 และ 1,020 รวมความยาว 1,500, 1,500, 1,040 bytes; offsets =0,185,370 และ MF=1,1,0

Fragment offset นับหน่วย 8 bytes ไม่ใช่ byte จึงได้ 1,480/8=185 Header ของแต่ละชิ้นเพิ่ม overhead และถ้าชิ้นใดหาย datagram เดิมอาจประกอบไม่สำเร็จ การแบ่งระดับ TCP เป็น segment ก่อนส่งกับ IP fragmentation เป็นคนละขั้น

TTL, ICMP และ NAT

TTL ลดลงเมื่อผ่าน router หากหมดจะทิ้งและอาจส่ง ICMP แจ้งช่วยหยุด packet วนลูป ไม่ใช่ตัวจับเวลาวินาทีตามการลดค่าจริงใน forwarding ทั่วไป Traceroute ใช้การหมดอายุแบบนี้เพื่อสืบเส้นทางในแบบที่สไลด์อธิบาย

NAT แปลที่อยู่ ส่วน NAPT/PAT แปลทั้ง IP กับ port ทำให้หลายการเชื่อมต่อภายในแชร์ที่อยู่ภายนอกได้ โดยเก็บ mapping เช่น 10.0.0.2:50000 ↔ external:62001 NAT ไม่เท่ากับ firewall แม้อุปกรณ์หนึ่งมักทำทั้งสองหน้าที่

กลับสารบัญ ↑

IPv6 กับการเปลี่ยนผ่าน

IPv6 base header มี 40 bytes และใช้ส่วนขยายสำหรับข้อมูลเพิ่มตามแบบ ไม่มี header checksum แบบ IPv4 และ router IPv6 ไม่แบ่ง fragment แบบ IPv4 การเปลี่ยนผ่านอาจใช้ dual stack และ tunneling ซึ่งห่อ packet หนึ่งไว้ในอีก protocol ไม่ใช่เปลี่ยนเลข IPv4 เป็น IPv6 ด้วยการเติมศูนย์อย่างเดียว

ลองตอบ: Datagram 4,000 bytes ตัวอย่างนี้ fragment สุดท้าย length เท่าไร

เฉลยและเหตุผล: 1,040 bytes ประกอบด้วย header 20 กับ payload ที่เหลือ 1,020 ต้องไม่ลืม header ของชิ้นสุดท้าย

ลองตอบ: NAT ทำให้ IP ปลายทางเปลี่ยนทุก hop เหมือน MAC หรือไม่

เฉลยและเหตุผล: ไม่ NAT เป็นการแปลที่อุปกรณ์ที่ทำหน้าที่นี้ ส่วน router ปกติไม่เปลี่ยน source/destination IP เพียงเพราะส่งผ่าน

จำให้ได้: IP best-effort; offset หน่วย 8 bytes; TTL กันวน; NAT กับ firewall คนละหน้าที่

บล็อกข้อความ 22 — An IPv4 packet has arrived with the first 8 bits as shown:

อ่านข้อความต้นฉบับที่สกัดได้ (อังกฤษตามไฟล์)
An IPv4 packet has arrived with the first 8 bits as shown:
01000010
The receiver discards the packet. Why?
Solution
There is an error in this packet. The 4 leftmost bits (0100) show the version, which is correct. The next 4 bits (0010) show an invalid header length (2 × 4 = 8). The minimum number of bytes in the header must be 20. The packet has been corrupted in transmission.

บล็อกข้อความ 23 — In an IPv4 packet, the value of HLEN is 1000 in binary. How many bytes of options are being carried by this packet?

อ่านข้อความต้นฉบับที่สกัดได้ (อังกฤษตามไฟล์)
In an IPv4 packet, the value of HLEN is 1000 in binary. How many bytes of options are being carried by this packet?
Solution
The HLEN value is 8, which means the total number of bytes in the header is 8 × 4, or 32 bytes. The first 20 bytes are the base header, the next 12 bytes are the options.

An IPv4 packet has arrived with the first few hexadecimal digits as shown.
0x45000028000100000102 . . .
How many hops can this packet travel before being dropped? The data belong to what upper-layer protocol?
Solution
To find the time-to-live field, we skip 8 bytes. The time-to-live field is the ninth byte, which is 01. This means the packet can travel only one hop. The protocol field is the next byte (02), which means that the upper-layer protocol is IGMP.

A packet has arrived with an M bit value of 0. Is this the first fragment, the last fragment, or a middle fragment? Do we know if the packet was fragmented?
Solution
If the M bit is 0, it means that there are no more fragments; the fragment is the last one. However, we cannot say if the original packet was fragmented or not. A non-fragmented packet is considered the last fragment.

A packet has arrived with an M bit value of 1. Is this the first fragment, the last fragment, or a middle fragment? Do we know if the packet was fragmented?

If the M bit is 1, it means that there is at least one more fragment. This fragment can be the first one or a middle one, but not the last one. We don’t know if it is the first one or a middle one; we need more information (the value of the fragmentation offset).

Solution
The first byte number is 100 × 8 = 800. The total length is 100 bytes, and the header length is 20 bytes (5 × 4), which means that there are 80 bytes in this datagram. If the first byte number is 800, the last byte number must be 879.
