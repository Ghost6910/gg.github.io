Network management มีหลายหน้าที่ที่สรุปเป็น FCAPS: Fault ตรวจ/แก้ความผิดปกติ, Configuration การตั้งค่า, Accounting การใช้ทรัพยากร, Performance ประสิทธิภาพ และ Security ความปลอดภัย เครื่องมือดูกราฟอย่างเดียวจึงไม่ครอบคลุมทั้งหมด

Manager เป็นระบบบริหารที่ส่งคำขอและรับเหตุการณ์ Agent อยู่บนอุปกรณ์ที่ถูกจัดการ MIB เป็นแบบจำลองข้อมูลวัตถุที่บริหารได้ ระบุด้วย OID ส่วน SMI กำหนดโครงสร้างและรูปแบบที่ใช้อธิบายข้อมูล ไม่ใช่เอาสามชื่อมาใช้แทนกัน

SNMP Messages

Get ขอค่า, GetNext เดินลำดับวัตถุ, GetBulk ช่วยดึงหลายค่าตามเวอร์ชัน, Set ขอเปลี่ยนค่า, Response ตอบ และ Trap/Inform ส่งเหตุการณ์ โดยรายละเอียดขึ้นกับ SNMP version และอุปกรณ์

Polling ช่วยเห็นข้อมูลเป็นช่วง แต่เพิ่ม traffic และอาจไม่เห็นเหตุการณ์สั้นระหว่างรอบ Event notification แจ้งได้ทันเหตุการณ์แต่ต้องคิดการสูญหาย การยืนยัน และการเก็บประวัติ การออกแบบจริงใช้ร่วมกันได้

ตัวอย่างอ่าน Counter

ถ้า counter จำนวน octets เพิ่ม 7,500,000 ใน 60 วินาที อัตราเฉลี่ย =7,500,000×8/60=1,000,000 bit/s หรือ 1 Mb/s ต้องดูชนิด counter การวนกลับ และการ reset เมื่ออุปกรณ์ reboot ถ้าใช้ค่าปัจจุบันหารเวลาโดยไม่หาผลต่างจะผิด

SNMP community string ในระบบรุ่นเก่าต่างจากการยืนยันตัวตนและการปกป้องข้อความของรุ่นที่รองรับกลไกเพิ่ม ให้แยกบทเรียนเรื่อง protocol ออกจากสิทธิ์เข้าถึงอุปกรณ์จริง โดยเฉพาะ Set ที่เปลี่ยนการตั้งค่าได้

ลองตอบ: MIB คือโปรโตคอลที่ส่งบนสายหรือไม่

เฉลยและเหตุผล: ไม่ MIB อธิบายข้อมูลบริหาร ส่วน SNMP เป็นโปรโตคอลแลกข้อความที่เข้าถึงข้อมูลเหล่านั้น

ลองตอบ: counter เพิ่ม 1,000 bytes ใน 2 วินาทีเท่ากับ 500 bit/s หรือไม่

เฉลยและเหตุผล: ไม่ 500 bytes/s ต้องคูณ 8 จึงเป็น 4,000 bit/s

จำให้ได้: จำ FCAPS, Manager/Agent/MIB/SMI และใช้ผลต่าง counter ต่อช่วงเวลา

Then we have two integers defining maximum size (1024) and message ID (64). The header is a sequence of length 12, which we left blank for simplicity. There is one integer, version (version 3). The whole message is a sequence of 52 bytes. Figure 28.24 shows the actual message sent by the manager station (client) to the agent (server).
