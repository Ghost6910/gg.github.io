351 บท 5: Link Layer, LAN, MPLS และเส้นทางเปิดเว็บ

เปิดบทนี้ในเล่มรวม

บริการ Link Layer ที่ไม่เหมือนกันทุกเทคโนโลยี

Link layer ห่อ datagram เป็น frame บนลิงก์ มีการเข้าถึงช่องและตรวจข้อผิดพลาดตามระบบ บางเทคโนโลยีมี reliable delivery/flow control เพิ่ม บางแบบไม่ให้ จึงไม่ยกบริการหนึ่งไปเหมารวมทุก link

Adaptor/NIC จัดการส่วน link และ physical จำนวนมากร่วมกับ driver/OS ที่เครื่องปลายทาง ภาพ logical layer ไม่ได้แปลว่าทั้งชั้นเป็นโปรแกรมใน CPU อย่างเดียว

กลับสารบัญ ↑

ARP และ MAC ตามแต่ละ Hop

สมมติ A อยู่ LAN1 ส่งให้ B อยู่ LAN2 ผ่าน R: IP ต้นทาง A และ IP ปลายทาง B ใส่ใน datagram; frame แรกมี MAC A→MAC R ขาฝั่ง LAN1; R ส่ง frame ใหม่เป็น MAC R ขาฝั่ง LAN2→MAC B ในกรณีพื้นฐาน IP คู่เดิมยังคงอยู่

หาก LAN2 มี switch สวิตช์ไม่เปลี่ยน IP และไม่จำเป็นต้องเปลี่ยน source/destination MAC เพียงเพราะ frame ผ่านพอร์ต มันเลือกขาออกตามตาราง MAC ของ VLAN นั้น

กลับสารบัญ ↑

Error Detection และ MAC Protocols

Parity, checksum และ CRC เพิ่ม redundancy เพื่อช่วยตรวจผิดตามความสามารถโค้ด ไม่รับรอง authenticity ทบทวนบท 10 ส่วนการแบ่งช่อง TDMA/FDMA, ALOHA และ CSMA ดูบท 12 โดยผูกกับสมมติฐานของสื่อร่วม

โจทย์ ALOHA ที่ถาม 1/e หรือ 1/(2e) เป็นประสิทธิภาพสูงสุดในแบบจำลองเฉพาะ ไม่ใช่คำตอบประสิทธิภาพ Ethernet หรือ Wi-Fi ทุกระบบ และ Ethernet full-duplex ที่ต่อ switch ไม่ใช้การชนแบบ hub

กลับสารบัญ ↑

VLAN และ MPLS

VLAN แบ่ง broadcast domain เชิงตรรกะบน LAN ส่วน MPLS ส่งต่อตาม label บนเส้นทางที่สร้างไว้ มีตาราง incoming label → outgoing label/interface ค่า label มีความหมายตามบริบท ไม่จำเป็นต้องคงเลขตลอดเส้นทาง

Label switching ไม่ได้แปลว่า “ลืม IP ทั้งระบบ” เพราะ IP routing/control plane ยังเกี่ยวข้องในการสร้างเส้นทางตามระบบ และการเลือกเส้น MPLS อาจมีเงื่อนไข traffic engineering แตกต่างจาก shortest IP route ปกติ

กลับสารบัญ ↑

Data Center Networks

Data center มีเครื่องจำนวนมาก เชื่อมผ่าน rack switches และชั้นเครือข่ายอื่น เน้นความจุระหว่างเครื่องและเส้นทางหลายทาง Load balancer ในรูปทำหน้าที่กระจายงานไปบริการปลายทางต่างจากการ switch frame อย่างเดียว จุดคอขวดอาจเป็น uplink แม้ทุกเครื่องมี NIC เร็ว

กลับสารบัญ ↑

สังเคราะห์: ตั้งแต่ต่อโน้ตบุ๊กจนเปิดเว็บ

  1. เชื่อมลิงก์กายภาพ/ไร้สายให้ได้ก่อน เช่น Ethernet link หรือ Wi-Fi association
  2. ได้ IP, mask, gateway, DNS เช่นผ่าน DHCP โดยตรวจค่าที่ได้
  3. แยกชื่อ host จาก URL และถาม DNS หากไม่มีข้อมูลใน cache
  4. ถ้า DNS หรือเว็บอยู่นอก subnet ให้หา next hop ผ่าน routing แล้ว ARP หา MAC ของ gateway ในกรณี IPv4/Ethernet
  5. ส่ง frame ผ่าน switch ไป router; router เลือกเส้นตาม IP และเปลี่ยนกรอบลิงก์ตามขาออก
  6. ตั้ง transport ที่แอปต้องใช้ เช่น TCP handshake ในตัวอย่าง HTTP/1.x และ TLS เพิ่มสำหรับ HTTPS ตามระบบ
  7. ส่ง HTTP request รับ response และเรียก objects เพิ่มตามหน้าเว็บ; ใช้ buffer, ACK, retransmission ตาม protocol ที่เกี่ยวข้อง
  8. แยกอาการเมื่อเสีย: link, address, gateway, DNS, transport, TLS และ application ต้องตรวจต่างจุด
ลองตอบ: ARP ก่อน HTTP เสมอทุก request หรือไม่

เฉลยและเหตุผล: ไม่ ถ้ามี cache, connection เดิม หรือกลไกอื่นตามระบบ อาจไม่ต้อง ARP ใหม่ ภาพในสไลด์เป็นสถานการณ์ตัวอย่างที่มีเงื่อนไข

ลองตอบ: VLAN กับ MPLS ทำสิ่งเดียวกันหรือไม่

เฉลยและเหตุผล: ไม่ VLAN แบ่งโดเมนชั้น 2 ส่วน MPLS ใช้ label ในการส่งต่อตามโครงข่ายและเส้นทางที่กำหนด แม้ทั้งคู่มีการใส่ข้อมูลกำกับเพิ่มเติม

จำให้ได้: ใช้สถานการณ์เปิดเว็บเชื่อมทุกชั้น แล้วถามแต่ละขั้นว่า protocol ไหนใช้ address อะไร

แปลและเรียบเรียงหลักการ

Single-bit error คือเปลี่ยนค่าหนึ่งบิต ส่วน Burst error มีความผิดพลาดกระจายอยู่ในช่วงหนึ่ง โดยความยาว burst นับจากบิตผิดแรกถึงบิตผิดสุดท้าย ไม่ได้แปลว่าทุกบิตระหว่างนั้นผิดทั้งหมด

Redundancy คือเพิ่มข้อมูลที่มีความสัมพันธ์กับข้อมูลจริง เพื่อให้ผู้รับตรวจหรือแก้ข้อผิดพลาดได้ Error detection บอกว่าพบความผิดปกติ ส่วน Error correction ต้องมีข้อมูลพอระบุค่าที่ถูกต้องหรืออาศัยการส่งซ้ำ การมี checksum ไม่ได้แปลว่าแก้ข้อมูลได้เอง

Hamming distance และ Parity

Hamming distance คือจำนวนตำแหน่งบิตที่ต่างกันระหว่าง codeword สองคำ ถ้าระยะต่ำสุดของโค้ดคือ dmin จะรับประกันตรวจได้ถึง dmin−1 บิตผิด และแก้ได้ถึง ⌊(dmin−1)/2⌋ บิต ตัวอย่าง dmin=3 ตรวจได้ 2 และแก้ได้ 1

Even parity เพิ่มบิตให้จำนวน 1 รวมเป็นเลขคู่ เช่นข้อมูล 1011001 มี 1 สี่ตัว จึงเพิ่ม 0 ถ้ามีบิตเปลี่ยนจำนวนคี่จะตรวจพบ แต่ถ้าเปลี่ยนจำนวนคู่บางรูปแบบจะไม่พบ Two-dimensional parity เพิ่มการตรวจตามแถวและคอลัมน์ ช่วยระบุตำแหน่งผิดหนึ่งบิตได้ตามโครงสร้าง

สำหรับ Hamming code แก้บิตผิดหนึ่งบิต จำนวน parity bits r ต้องพอให้ 2^r ≥ m+r+1 เมื่อข้อมูล m=4 ใช้ r=3 เพราะ 8≥8 แต่สมการนี้อย่างเดียวไม่ได้บอกตำแหน่ง parity ต้องวางตามรหัสที่ออกแบบ

กลับสารบัญ ↑

CRC แบบค่อยเป็นค่อยไป

Cyclic Redundancy Check มองบิตเป็นพหุนามเหนือ GF(2) ใช้ XOR แทนการลบ ผู้ส่งเติมศูนย์ r บิตเมื่อ generator มี degree r แล้วหารเอาเศษ r บิตมาแทนท้ายข้อมูล ผู้รับหาร codeword ด้วย generator เดียวกัน หากเศษไม่เป็นศูนย์แสดงว่าตรวจพบข้อผิดพลาด

ตัวอย่าง D=1101, G=1011 ซึ่งมี degree 3: เติมศูนย์เป็น 1101000 แล้วหาร XOR ได้เศษ 001 จึงส่ง 1101001 เมื่อนำ 1101001 หารด้วย 1011 ได้เศษ 000 ให้ลองเขียนการหารทีละขั้นเพื่อเห็นว่าห้ามใช้การลบที่มีการยืมแบบเลขฐานสองทั่วไป

เศษศูนย์หมายถึง “ไม่ตรวจพบ” ไม่ใช่หลักฐานว่าไม่มีข้อผิดพลาดทุกชนิด ความสามารถตรวจขึ้นกับ generator และรูปแบบ error โค้ดที่ดีรับประกันบางกลุ่ม แต่ยังมี error pattern ที่เป็นพหุคูณ generator แล้วหลุดได้

Internet checksum

แบ่งข้อมูลเป็นคำ 16 บิต บวกแบบ one's complement โดยนำ carry สูงสุดวนกลับมาบวกด้านล่าง จากนั้นกลับบิตผลรวมเป็น checksum ผู้รับรวมข้อมูลกับ checksum ถ้าได้บิต 1 ทั้งหมดตามแบบจำลองถือว่าผ่านการตรวจ ไม่ใช่บวกธรรมดาแล้วทิ้ง carry

ลองตอบ: โค้ดที่ dmin=5 ตรวจและแก้ผิดได้เท่าไร

เฉลยและเหตุผล: รับประกันตรวจได้สูงสุด 4 บิต และแก้ได้สูงสุด 2 บิต โดยสองข้อความนี้อธิบายความสามารถคนละโหมดการใช้งาน

ลองตอบ: CRC ผ่านแล้วรับประกันข้อมูลแท้จากผู้ส่งหรือไม่

เฉลยและเหตุผล: ไม่ CRC ตรวจความผิดพลาดจากสัญญาณตามแบบโค้ด ไม่ได้ยืนยันตัวตนหรือป้องกันผู้โจมตีแก้ข้อมูลแล้วคำนวณ CRC ใหม่

จำให้ได้: Parity / CRC / Checksum ใช้ตรวจผิด; แยกจากการยืนยันความถูกต้องเชิงความปลอดภัยด้วย MAC หรือลายเซ็น

ประสิทธิภาพ ALOHA

ในแบบจำลอง Poisson ที่ใช้สอน Pure ALOHA มี S=G e^(−2G) ค่าสูงสุด 1/(2e)≈0.184 ส่วน Slotted ALOHA มี S=G e^(−G) ค่าสูงสุด 1/e≈0.368 ตัวเลขนี้มีสมมติฐานเรื่องการมาถึง ขนาด frame และการชน ไม่ใช่ประสิทธิภาพ Wi-Fi จริง

CSMA ฟังก่อนส่ง แต่ยังชนได้เพราะ propagation delay: สองเครื่องที่อยู่ห่างอาจต่างคิดว่าช่องว่าง ก่อนคลื่นของอีกฝ่ายเดินทางถึง CSMA/CD ฟังการชนระหว่างส่ง แล้วหยุดและถอยรอ ส่วน CSMA/CA พยายามลดการชนด้วยการรอ/backoff และกลไกตอบรับตามระบบ

การควบคุมและแบ่งช่อง

FDMA แบ่งความถี่, TDMA แบ่งเวลา และ CDMA ใช้ code แยกสัญญาณ การทำโจทย์ CDMA ต้องระบุการแทนบิตเป็น +1/−1 และสมบัติ code แล้วจึงคูณ/รวมและ correlate ไม่ควรใช้ XOR แทนทุกขั้นโดยไม่ดูนิยาม

เสริมติว Ethernet กับ Wi-Fi

Ethernet แบบ half-duplex ใช้ CSMA/CD แต่ Ethernet full-duplex ที่ต่อ switch point-to-point ไม่ต้องแก้การชนแบบ shared medium ส่วน Wi-Fi ใช้แนว CSMA/CA เพราะการตรวจการชนขณะส่งทำได้ยากและมีปัญหา hidden node

ลองตอบ: ฟังก่อนส่งแล้วทำไมยังชน

เฉลยและเหตุผล: เพราะสัญญาณเดินทางใช้เวลา แต่ละโหนดไม่ได้เห็นสถานะอีกฝั่งทันที จึงเริ่มส่งก่อนรู้ว่ามีอีกฝ่ายส่งแล้วได้

ลองตอบ: Wi-Fi เห็น SSID ต่างกันหมายความว่าไม่แย่งคลื่นหรือไม่

เฉลยและเหตุผล: ไม่ SSID เป็นชื่อเครือข่าย หากใช้ช่องทับซ้อนหรือใช้ช่องร่วมกันยังมีการรบกวนหรือแย่ง airtime ได้

จำให้ได้: Random access ไม่ได้แปลว่าไร้กติกา และอย่าใช้ CSMA/CD อธิบาย switched full-duplex ทุกกรณี

แปลและเรียบเรียง Ethernet

Ethernet เป็นตระกูลเทคโนโลยี LAN ที่เกี่ยวข้องกับ IEEE 802.3 ครอบคลุมส่วน MAC และ physical หลายรูปแบบ โครงสร้างกายภาพอาจเป็น bus ในระบบเก่า หรือ star ต่อ switch ในระบบที่เรียนกันทั่วไป ต้องแยก topology ทางกายภาพจากวิธีใช้ช่องร่วมกัน

MAC address แบบ Ethernet ยาว 48 บิตหรือ 6 bytes มักเขียนฐานสิบหก 6 คู่ เช่น 02:00:00:00:00:01 และ FF:FF:FF:FF:FF:FF เป็น broadcast บน Ethernet MAC มีทั้งแบบกำหนดโดยผู้ผลิตและแบบ locally administered จึงไม่ควรอธิบายว่าห้ามเปลี่ยนเด็ดขาด

โครงสร้าง Frame

Ethernet II มี destination MAC, source MAC, EtherType, payload/padding และ FCS ส่วน preamble/SFD ใช้ประสานและเริ่ม frame ในการนับขนาดต้องอ่านว่ารวมส่วนใด กรอบพื้นฐานแบบไม่ติด VLAN มี 64–1518 bytes จาก destination MAC ถึง FCS ไม่รวม preamble/SFD และ inter-frame gap

Payload พื้นฐานอยู่ในช่วง 46–1500 bytes หากข้อมูลสั้นต้องเติม padding ให้ถึงขนาดขั้นต่ำ FCS ใช้ตรวจความผิดพลาดและ frame ที่ผิดจะถูกทิ้ง แต่ Ethernet ไม่ให้ ACK และ retransmission แบบ TCP

Hub ทำซ้ำสัญญาณไปพอร์ตอื่น ทำให้แบ่ง collision domain เดียว ส่วน switch สร้างจุดเชื่อมต่อแยกแต่ละพอร์ต Full-duplex ส่งและรับพร้อมกันบนลิงก์นั้นได้โดยไม่มี collision แบบ Ethernet shared medium

Minimum frame ในบริบท CSMA/CD เกี่ยวกับการให้ผู้ส่งยังส่งอยู่เมื่อผลการชนจากปลายไกลเดินทางกลับ การอธิบายเหตุผลเชิงประวัตินี้ช่วยเข้าใจข้อกำหนด แต่ห้ามสรุปว่า full-duplex ปัจจุบันยังต้องแข่งส่งเหมือน hub

ลองตอบ: 100 Mb/s Ethernet ให้แอปส่งข้อมูลได้ 100 Mb/s เต็มหรือไม่

เฉลยและเหตุผล: โดยทั่วไปข้อมูลแอปมี overhead หลายชั้นและมีช่วงว่างระหว่าง frame อัตราลิงก์จึงต่างจาก goodput

VLAN และ Trunk

VLAN แบ่งเครือข่ายชั้น 2 เชิงตรรกะให้พอร์ตคนละกลุ่มอยู่คนละ broadcast domain แม้ใช้ switch ตัวเดียวกัน การสื่อสารข้าม VLAN ต้องมีการ route ผ่าน router หรืออุปกรณ์ชั้น 3 และใช้ addressing ที่เหมาะสม

Access port ส่ง traffic ของ VLAN เดียวให้เครื่องปลายทางในรูปแบบปกติ ส่วน trunk ขน traffic หลาย VLAN บนลิงก์เดียวด้วยการระบุ VLAN เช่น 802.1Q ต้องตั้ง VLAN ที่อนุญาตและการตีความ untagged/native ให้สอดคล้องตามระบบ

Backbone เป็นส่วนเชื่อมเครือข่ายย่อยเข้าด้วยกัน อาจออกแบบเป็น bus, star หรือหลายระดับ การรวมศูนย์ช่วยดูแลแต่ต้องคำนึงจุดล้มเหลวและความจุ uplink

ลองตอบ: สวิตช์รู้ MAC ปลายทางได้อย่างไร

เฉลยและเหตุผล: เรียนรู้จาก source MAC ของ frame ที่เคยเข้ามา ไม่ได้ถาม DNS และไม่ได้อ่าน routing table เพื่อเรียนรู้ MAC

ลองตอบ: เครื่องต่าง VLAN แต่ IP subnet เดียวกันจะคุยกันได้เองหรือไม่

เฉลยและเหตุผล: โดยทั่วไปไม่ เพราะ ARP broadcast ไม่ข้าม VLAN การกำหนด subnet เดียวกันข้ามโดเมนชั้น 2 ทำให้การเข้าถึงผิดจากสมมติฐานปกติ ต้องออกแบบและ route ให้ถูก

จำให้ได้: Switch เรียน source → เลือกด้วย destination; VLAN แยก broadcast, router เชื่อมข้ามเครือข่าย

Cyclic redundancy check (ข้าม)
 เป็นโค้ดการตรวจสอบความเสียหายที่มีประสิทธิภาพ
 ดูข้อมูลเป็นบิต, D, แทนเลขฐานสอง
 choose r+1 bit pattern (generator), G
 goal: choose r CRC bits, R, such that
      <D,R> exactly divisible by G (modulo 2)
      receiver knows G, divides <D,R> by G. If non-zero remainder: error detected!
      can detect all burst errors less than r+1 bits
   ใช้ทั่วไป (Ethernet, 802.11 WiFi, ATM)
