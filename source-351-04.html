จาก Forwarding Table ไปยังการเดินทางจริง

เมื่อ router รับ frame จะตรวจข้อมูลที่จำเป็น ถอดส่วนชั้นลิงก์ แล้วใช้ destination IP หาเส้นใน forwarding table ต่อไปสร้าง frame สำหรับลิงก์ขาออก ฝั่งขาเข้าและขาออกอาจเป็นเทคโนโลยีต่างกัน ไม่จำเป็นต้องเป็น Ethernet ตลอด

ส่วนประกอบ router ที่สไลด์ใช้คือ input ports, switching fabric, output ports และ routing processor Queue เกิดได้ทั้งขาเข้าและขาออกตามข้อจำกัด Head-of-line blocking คือ packet หัวคิวกีดขวาง packet หลังแม้หลังจะไป output ที่ว่างได้

Subnet ไม่ใช่จำนวนเครื่องที่ต่อ switch เท่านั้น

Subnet เป็นกลุ่ม interface ที่สื่อสารถึงกันในลิงก์/โครงสร้างที่ออกแบบโดยไม่ผ่าน router สำหรับ subnet นั้น Router มีหลาย interface จึงอยู่หลาย subnet ได้ และการนับ subnet ในรูปต้องดูแต่ละ LAN รวมถึงลิงก์ระหว่าง router ตาม IP ที่กำหนด

IP address ผูกกับ interface เป็นหลัก เครื่องเดียวหลาย interface อาจมีหลาย address ไม่ใช่หนึ่งเครื่องต้องมี IPv4 เพียงหนึ่งเลขตลอดไป การคิด subnet ให้เริ่มจาก prefix และขอบเขตลิงก์

DHCP, NAT และ IPv6 เชื่อมอย่างไร

เครื่องได้ค่า IP/mask/gateway/DNS จาก DHCP ก่อนจึงใช้ subnet decision และ routing ตามปกติ หากผ่าน NAT ที่ทางออก mapping อาจแปล source IP/port เป็นภายนอก ส่วน DNS เป็นการค้นชื่อ ไม่ได้เป็นตัวแจก address ให้ interface แทน DHCP

IPv6 แก้ขนาด address และโครงสร้างบางส่วน แต่การเปลี่ยนผ่านต้องรองรับเครือข่ายหลายแบบ อ่านบท 19–21 เพื่อแยก address format, datagram และ protocol ควบคุม

Routing ตามลำดับการคิด

  1. แปลงโจทย์เป็น graph ที่มี node, edge และ cost ให้ตรงภาพ
  2. ระบุว่าใช้ link-state หรือ distance-vector และรู้อะไรบ้างตอนเริ่ม
  3. คำนวณแต่ละรอบพร้อม predecessor หรือ next hop ไม่บันทึกแค่ cost สุดท้าย
  4. นำเส้นทางที่ได้ไปสร้าง forwarding table ที่ต้นทางนั้น
  5. ถ้าข้าม AS ให้พิจารณานโยบายและ attributes ตามที่กำหนด ไม่ใช้ Dijkstra แทน BGP โดยอัตโนมัติ

Multicast กับ Tree

Shortest-path tree จาก source อาจต่างจาก shared tree ที่ลดโครงสร้างรวม บางต้นไม้เหมาะต่อระยะทางแต่ไม่ใช่ต้นทุนรวมต่ำสุด Steiner tree เป็นโจทย์ต้นทุนรวมที่ต่างจากการหา shortest path ถึงแต่ละคน

PIM sparse mode ใช้แนวรวมกลุ่มผ่านจุดที่กำหนดในแบบที่สไลด์อธิบาย ส่วน dense mode เริ่มจากแนวกระจายกว้างแล้วตัดสาขา ความแตกต่างนี้ดูความกระจายของสมาชิก ไม่ใช่ดูจำนวนบิตใน multicast address

ลองตอบ: Router มี 3 interfaces ต้องมี IP เดียวหรือไม่

เฉลยและเหตุผล: ไม่ โดยทั่วไปแต่ละ interface IP ต้องมี address ที่สัมพันธ์ subnet ของตนตามการตั้งค่า และอาจมีหลาย address ได้ตามระบบ

ลองตอบ: ได้ route cost แล้วตอบ next hop อย่างไร

เฉลยและเหตุผล: ย้อน predecessor จากปลายทางกลับต้นทาง แล้วหยิบโหนดถัดจากต้นทาง ไม่ใช่ใส่ปลายทางทุกบรรทัดเป็น next hop

จำให้ได้: อ่านร่วม 19–22; ฝึก subnet, LPM, fragment และ routing เป็นโจทย์คนละแบบ

แปลและเรียบเรียงบริการ IP

IP ส่ง packet แบบ connectionless และ best-effort ไม่มีการรับประกันว่าถึง ครบ เรียง หรือไม่มีซ้ำด้วยตัว IP เอง ความน่าเชื่อถืออาจถูกเพิ่มโดย transport หรือ application แยก routing หาเส้นทางออกจาก forwarding เลือกขาออกให้ packet หนึ่งตัว

IPv4 header มีข้อมูลเช่น version, header length, total length, identification, flags, fragment offset, TTL, protocol, header checksum และ source/destination IP ค่า protocol ระบุชนิดข้อมูลชั้นบน ไม่ใช่ TCP/UDP port

Fragmentation แบบละเอียด

MTU เป็นขนาด packet ชั้นที่กำหนดซึ่งลิงก์รองรับ หาก IPv4 datagram ใหญ่เกินและอนุญาต fragmentation อาจแบ่งเป็น fragments โดยแต่ละ fragment มี IP header ของตนเอง และนำไปประกอบกลับที่ปลายทาง

ตัวอย่าง IPv4 total length 4,000 bytes, header 20, MTU 1,500: payload เดิม 3,980; แต่ละชิ้นที่ไม่ใช่สุดท้ายบรรทุกได้ 1,480 ซึ่งหาร 8 ลงตัว ได้ชิ้น payload 1,480, 1,480 และ 1,020 รวมความยาว 1,500, 1,500, 1,040 bytes; offsets =0,185,370 และ MF=1,1,0

Fragment offset นับหน่วย 8 bytes ไม่ใช่ byte จึงได้ 1,480/8=185 Header ของแต่ละชิ้นเพิ่ม overhead และถ้าชิ้นใดหาย datagram เดิมอาจประกอบไม่สำเร็จ การแบ่งระดับ TCP เป็น segment ก่อนส่งกับ IP fragmentation เป็นคนละขั้น

TTL, ICMP และ NAT

TTL ลดลงเมื่อผ่าน router หากหมดจะทิ้งและอาจส่ง ICMP แจ้งช่วยหยุด packet วนลูป ไม่ใช่ตัวจับเวลาวินาทีตามการลดค่าจริงใน forwarding ทั่วไป Traceroute ใช้การหมดอายุแบบนี้เพื่อสืบเส้นทางในแบบที่สไลด์อธิบาย

NAT แปลที่อยู่ ส่วน NAPT/PAT แปลทั้ง IP กับ port ทำให้หลายการเชื่อมต่อภายในแชร์ที่อยู่ภายนอกได้ โดยเก็บ mapping เช่น 10.0.0.2:50000 ↔ external:62001 NAT ไม่เท่ากับ firewall แม้อุปกรณ์หนึ่งมักทำทั้งสองหน้าที่

IPv6 กับการเปลี่ยนผ่าน

IPv6 base header มี 40 bytes และใช้ส่วนขยายสำหรับข้อมูลเพิ่มตามแบบ ไม่มี header checksum แบบ IPv4 และ router IPv6 ไม่แบ่ง fragment แบบ IPv4 การเปลี่ยนผ่านอาจใช้ dual stack และ tunneling ซึ่งห่อ packet หนึ่งไว้ในอีก protocol ไม่ใช่เปลี่ยนเลข IPv4 เป็น IPv6 ด้วยการเติมศูนย์อย่างเดียว

ลองตอบ: Datagram 4,000 bytes ตัวอย่างนี้ fragment สุดท้าย length เท่าไร

เฉลยและเหตุผล: 1,040 bytes ประกอบด้วย header 20 กับ payload ที่เหลือ 1,020 ต้องไม่ลืม header ของชิ้นสุดท้าย

ลองตอบ: NAT ทำให้ IP ปลายทางเปลี่ยนทุก hop เหมือน MAC หรือไม่

เฉลยและเหตุผล: ไม่ NAT เป็นการแปลที่อุปกรณ์ที่ทำหน้าที่นี้ ส่วน router ปกติไม่เปลี่ยน source/destination IP เพียงเพราะส่งผ่าน

จำให้ได้: IP best-effort; offset หน่วย 8 bytes; TTL กันวน; NAT กับ firewall คนละหน้าที่

DHCP

DHCP ช่วยแจก IP และข้อมูลเช่น mask, gateway, DNS มีลำดับที่จำว่า DORA: Discover → Offer → Request → ACK ในกรณีเริ่มต้นมาตรฐาน ผู้ใช้ยังไม่มี IP จึงอาจใช้ 0.0.0.0 และ broadcast ในการเริ่มต้น มี UDP port server 67 และ client 68

DHCP lease มีอายุและมีขั้นต่ออายุ ข้อความทุกขั้นไม่ได้ต้องเป็น broadcast ในทุกสถานการณ์ หาก server อยู่อีก subnet อาจใช้ DHCP relay ส่งต่ออย่างเหมาะสม ดังนั้น DHCP ทำงานข้าม router ได้เมื่อออกแบบ relay ไม่ใช่บอกว่า broadcast ไม่ผ่าน router แล้วสรุปว่าใช้ข้าม subnet ไม่ได้เลย

ICMP และการวินิจฉัย

ICMP ส่งข้อความควบคุม/แจ้งปัญหา เช่น destination unreachable, time exceeded และ echo request/reply ไม่ได้ทำให้ IP กลายเป็น reliable transport Ping ผ่านหมายถึงมีการตอบสนอง ICMP ตามเงื่อนไขทดสอบ แต่ ping ไม่ผ่านอาจถูกกรองหรือปลายทางไม่ตอบ จึงยังสรุปว่าเครื่องดับอย่างเดียวไม่ได้

IGMP และกลุ่ม Multicast

Multicast ส่งไปยังกลุ่มผู้รับที่สนใจ ไม่ใช่ broadcast ไปทุกเครื่อง IGMP ใช้จัดการ membership ระหว่าง host กับ router ที่เกี่ยวข้องใน IPv4 ส่วนการนำข้อมูล multicast ผ่านหลาย router ใช้ multicast routing อีกส่วนหนึ่ง

RARP และ BOOTP ที่พบในเอกสารเป็นบริบทพัฒนาการด้านการได้ที่อยู่ ต้องแยก RARP ที่เริ่มจาก hardware address ไปขอ IP ออกจาก ARP ที่ใช้ IP หา link address

ลองตอบ: เปิดเว็บต่าง subnet ต้อง ARP หาใครก่อน

เฉลยและเหตุผล: โดยพื้นฐานหา MAC ของ gateway บน LAN ตัวเอง เพื่อส่ง IP packet ที่มีปลายทางเป็นเว็บ server ไปให้ router ส่งต่อ

ลองตอบ: DHCP ได้ IP แล้วแต่เปิดชื่อเว็บไม่ได้ ต้องดูอะไร

เฉลยและเหตุผล: ตรวจค่า DNS และการเข้าถึง DNS รวมทั้ง gateway/routing การได้ lease ไม่ยืนยันว่าทุกค่าถูกหรือ server ภายนอกเข้าถึงได้

จำให้ได้: ARP อยู่ในขอบเขตลิงก์; DHCP แจกการตั้งค่า; ICMP ช่วยควบคุม/วินิจฉัย; IGMP จัด membership

Link State: Dijkstra

Link-state ให้โหนดมีภาพ topology กับ cost แล้วคำนวณเส้นทางสั้นที่สุดจากตัวเอง Dijkstra เริ่มกำหนด distance ของต้นทางเป็น 0 จากนั้นเลือกโหนดที่ยังไม่ยืนยันซึ่งมี distance ต่ำสุด และ relax ระยะไปเพื่อนบ้าน ทำซ้ำจนยืนยันโหนดที่ต้องการ

ตัวอย่าง A–B=2, A–C=5, B–C=1, B–D=4, C–D=1: เริ่ม B=2,C=5,D=∞; เลือก B แล้วปรับ C=3,D=6; เลือก C แล้วปรับ D=4; จบเส้น A→B→C→D cost 4 ตารางแต่ละรอบต้องจด predecessor เพื่อย้อนหาเส้นจริง

Distance Vector: Bellman-Ford

DV ใช้ Dₓ(y)=minᵥ{c(x,v)+Dᵥ(y)} โดย v เป็นเพื่อนบ้าน เลือกต้นทุนไปเพื่อน v บวกค่าที่ v โฆษณาว่าไป y ได้ แล้วเอาต่ำสุด ไม่จำเป็นต้องรู้ทั้ง topology แบบ LS

เมื่อข่าวลิงก์เสียแพร่ช้า อาจเกิด routing loop และ count-to-infinity กลไกเช่น split horizon หรือ poisoned reverse ช่วยบางกรณีแต่ไม่ได้แก้ loop ทุก topology ทั้งหมด

RIP, OSPF, BGP และนโยบาย

RIP เป็นตัวอย่าง distance vector ใช้ hop count และถือ 16 เป็น unreachable ในบริบทที่เรียน OSPF เป็น link-state ภายใน AS และมีการแบ่ง area ส่วน BGP ใช้แลกเส้นทางระหว่าง AS มี AS-PATH และ attributes อื่น การเลือกอาศัยนโยบาย ไม่ใช่เส้นที่ physical delay ต่ำสุดโดยอัตโนมัติ

Intra-AS เน้นการจัดเส้นทางภายในฝ่ายบริหารเดียว ส่วน Inter-AS ต้องคำนึงนโยบายและความสัมพันธ์องค์กร CIDR aggregation ช่วยลดจำนวน prefix แต่เส้นที่เฉพาะกว่ายังชนะด้วย longest prefix match

Broadcast และ Multicast Routing

Flooding ส่งสำเนาออกหลายขาเสี่ยงวน/ซ้ำ ต้องมีกลไกควบคุม Spanning tree ทำให้มีโครงสร้างต้นไม้ไม่มี loop ในขอบเขตที่ใช้ RPF ตรวจว่าข้อมูลเข้ามาทาง interface ที่เป็นเส้นย้อนกลับสู่ source ที่เหมาะสมก่อนส่งต่อ ส่วน prune ลดสาขาที่ไม่มีสมาชิก

Source-based tree สร้างต้นไม้ตามต้นทาง ส่วน shared tree ใช้โครงร่วมกันผ่านศูนย์กลางที่กำหนด PIM dense/sparse ในสไลด์ใช้แนวคิดต่างกันตามความหนาแน่นของสมาชิก ไม่ได้หมายถึงความหนาแน่นสายเคเบิล

ลองตอบ: /16 cost ต่ำกว่า /24 แต่ทั้งคู่ตรง destination ควรเลือกอะไร

เฉลยและเหตุผล: เริ่มจาก /24 เพราะเฉพาะกว่า การเทียบ metric ใช้ภายในชุดเส้นทางที่ระบบเลือกเปรียบเทียบตามกติกา ไม่เอา metric ต่าง prefix มาแทน longest prefix match

ลองตอบ: BGP เลือกทางสั้นที่สุดด้านเวลาเสมอหรือไม่

เฉลยและเหตุผล: ไม่ เป็น routing ตามนโยบายและ attributes จึงไม่รับประกัน latency ต่ำสุด

จำให้ได้: Forwarding ≠ routing; LPM เลือก prefix ก่อน; LS รู้ topology, DV ใช้ข่าวเพื่อน, BGP มีนโยบาย

เปิดบทนี้ในเล่มรวม

วิธีทำเป็นระบบ ไม่ต้องท่องทุกช่วง

  1. อ่าน /p แล้วหา h=32−p และจำนวน address 2^h
  2. สร้าง mask ด้วยบิต 1 จำนวน p ตัว ตามด้วย 0 ให้ครบ 32 บิต
  3. ทำ IP AND mask เพื่อหา network หรือใช้ช่วงก้าวใน octet ที่ไม่เต็ม
  4. หา broadcast = network +2^h−1 โดยคิดเป็นเลข 32 บิตหรือทด octet ให้ถูก
  5. หากเป็น subnet IPv4 ปกติถึง /30 ช่วง host คือ network+1 ถึง broadcast−1 และจำนวน host=2^h−2
  6. ถ้าถามจำนวน subnet ต้องระบุ parent /q แล้วคิด 2^(p−q) ไม่เดาเองจาก IP อย่างเดียว
  7. ตรวจว่า IP เดิมอยู่ระหว่าง network/broadcast และบิตส่วน host ของ network เป็นศูนย์ทั้งหมด

น้ำหนักบิตของหนึ่ง octet คือ 128,64,32,16,8,4,2,1 ตัวอย่าง 123=64+32+16+8+2+1 เขียน 01111011 ส่วน 4 ต้องเป็น 00000100 ไม่ใช่ 00000010

  2 N' = {u}

  15 until all nodes in N'
