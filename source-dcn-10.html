แปลและเรียบเรียงหลักการ

Single-bit error คือเปลี่ยนค่าหนึ่งบิต ส่วน Burst error มีความผิดพลาดกระจายอยู่ในช่วงหนึ่ง โดยความยาว burst นับจากบิตผิดแรกถึงบิตผิดสุดท้าย ไม่ได้แปลว่าทุกบิตระหว่างนั้นผิดทั้งหมด

Redundancy คือเพิ่มข้อมูลที่มีความสัมพันธ์กับข้อมูลจริง เพื่อให้ผู้รับตรวจหรือแก้ข้อผิดพลาดได้ Error detection บอกว่าพบความผิดปกติ ส่วน Error correction ต้องมีข้อมูลพอระบุค่าที่ถูกต้องหรืออาศัยการส่งซ้ำ การมี checksum ไม่ได้แปลว่าแก้ข้อมูลได้เอง

Hamming distance และ Parity

Hamming distance คือจำนวนตำแหน่งบิตที่ต่างกันระหว่าง codeword สองคำ ถ้าระยะต่ำสุดของโค้ดคือ dmin จะรับประกันตรวจได้ถึง dmin−1 บิตผิด และแก้ได้ถึง ⌊(dmin−1)/2⌋ บิต ตัวอย่าง dmin=3 ตรวจได้ 2 และแก้ได้ 1

Even parity เพิ่มบิตให้จำนวน 1 รวมเป็นเลขคู่ เช่นข้อมูล 1011001 มี 1 สี่ตัว จึงเพิ่ม 0 ถ้ามีบิตเปลี่ยนจำนวนคี่จะตรวจพบ แต่ถ้าเปลี่ยนจำนวนคู่บางรูปแบบจะไม่พบ Two-dimensional parity เพิ่มการตรวจตามแถวและคอลัมน์ ช่วยระบุตำแหน่งผิดหนึ่งบิตได้ตามโครงสร้าง

สำหรับ Hamming code แก้บิตผิดหนึ่งบิต จำนวน parity bits r ต้องพอให้ 2^r ≥ m+r+1 เมื่อข้อมูล m=4 ใช้ r=3 เพราะ 8≥8 แต่สมการนี้อย่างเดียวไม่ได้บอกตำแหน่ง parity ต้องวางตามรหัสที่ออกแบบ

กลับสารบัญ ↑

CRC แบบค่อยเป็นค่อยไป

Cyclic Redundancy Check มองบิตเป็นพหุนามเหนือ GF(2) ใช้ XOR แทนการลบ ผู้ส่งเติมศูนย์ r บิตเมื่อ generator มี degree r แล้วหารเอาเศษ r บิตมาแทนท้ายข้อมูล ผู้รับหาร codeword ด้วย generator เดียวกัน หากเศษไม่เป็นศูนย์แสดงว่าตรวจพบข้อผิดพลาด

ตัวอย่าง D=1101, G=1011 ซึ่งมี degree 3: เติมศูนย์เป็น 1101000 แล้วหาร XOR ได้เศษ 001 จึงส่ง 1101001 เมื่อนำ 1101001 หารด้วย 1011 ได้เศษ 000 ให้ลองเขียนการหารทีละขั้นเพื่อเห็นว่าห้ามใช้การลบที่มีการยืมแบบเลขฐานสองทั่วไป

เศษศูนย์หมายถึง “ไม่ตรวจพบ” ไม่ใช่หลักฐานว่าไม่มีข้อผิดพลาดทุกชนิด ความสามารถตรวจขึ้นกับ generator และรูปแบบ error โค้ดที่ดีรับประกันบางกลุ่ม แต่ยังมี error pattern ที่เป็นพหุคูณ generator แล้วหลุดได้

Internet checksum

แบ่งข้อมูลเป็นคำ 16 บิต บวกแบบ one's complement โดยนำ carry สูงสุดวนกลับมาบวกด้านล่าง จากนั้นกลับบิตผลรวมเป็น checksum ผู้รับรวมข้อมูลกับ checksum ถ้าได้บิต 1 ทั้งหมดตามแบบจำลองถือว่าผ่านการตรวจ ไม่ใช่บวกธรรมดาแล้วทิ้ง carry

ลองตอบ: โค้ดที่ dmin=5 ตรวจและแก้ผิดได้เท่าไร

เฉลยและเหตุผล: รับประกันตรวจได้สูงสุด 4 บิต และแก้ได้สูงสุด 2 บิต โดยสองข้อความนี้อธิบายความสามารถคนละโหมดการใช้งาน

ลองตอบ: CRC ผ่านแล้วรับประกันข้อมูลแท้จากผู้ส่งหรือไม่

เฉลยและเหตุผล: ไม่ CRC ตรวจความผิดพลาดจากสัญญาณตามแบบโค้ด ไม่ได้ยืนยันตัวตนหรือป้องกันผู้โจมตีแก้ข้อมูลแล้วคำนวณ CRC ใหม่

จำให้ได้: Parity / CRC / Checksum ใช้ตรวจผิด; แยกจากการยืนยันความถูกต้องเชิงความปลอดภัยด้วย MAC หรือลายเซ็น

Solution
This code guarantees the detection of up to three errors
(s = 3), but it can correct up to one error. In other words, 
if this code is used for error correction, part of its capability is wasted. Error correction codes need to have an odd minimum distance (3, 5, 7, . . . ).

Suppose our data is a list of five 4-bit numbers that we want to send to a destination. In addition to sending these numbers, we send the sum of the numbers. Otherwise, there is an error somewhere and the data are not accepted.

How can we represent the number 21 in one’s complement arithmetic using only four bits?
Solution
The number 21 in binary is 10101 (it needs five bits). We can wrap the leftmost bit and add it to the four rightmost bits. We have (0101 + 1) = 0110 or 6.

บล็อกข้อความ 87 — How can we represent the number −6 in one’s complement arithmetic using only four bits?

อ่านข้อความต้นฉบับที่สกัดได้ (อังกฤษตามไฟล์)
How can we represent the number −6 in one’s complement arithmetic using only four bits?
Solution
In one’s complement arithmetic, the negative or complement of a number is found by inverting all bits. Positive 6 is 0110; negative 6 is 1001. If we consider only unsigned numbers, this is 9. In other words, the complement of 6 is 9. Another way to find the complement of a number in one’s complement arithmetic is to subtract the number from 2n − 1 (16 − 1 in this case).
