แปลและเรียบเรียง Framing

Data link control ต้องกำหนดขอบเขต frame ควบคุมการไหล และจัดการข้อผิดพลาด Character-oriented framing ใช้ byte พิเศษคั่นและทำ byte stuffing เมื่อข้อมูลมีค่าเหมือนตัวคั่น ส่วน Bit-oriented framing ใช้รูปแบบบิตคั่นและ bit stuffing เพื่อไม่ให้ข้อมูลปลอมเป็นขอบเขต

ตัวอย่างแนว HDLC ใช้ flag 01111110 ผู้ส่งแทรก 0 หลังเจอ 1 ติดต่อกันห้าบิตในเนื้อหาที่ต้องทำ stuffing ผู้รับตัด 0 ที่แทรกออกตามกติกา การเพิ่มบิตนี้ต่างจากการเพิ่มบิต parity เพราะจุดประสงค์คือรักษาขอบเขต ไม่ใช่สร้างโค้ดตรวจผิด

Stop-and-Wait และ ARQ

Stop-and-Wait ส่งหนึ่ง frame แล้วรอ ACK ก่อนส่งต่อ ARQ รวมการตรวจข้อผิดพลาด เลขลำดับ การตอบรับ และ timer เพื่อส่งซ้ำเมื่อจำเป็น เลขลำดับช่วยแยกข้อมูลใหม่กับข้อมูลเดิมที่ส่งซ้ำเมื่อ ACK หาย

ถ้า ACK หาย ผู้ส่ง timeout แล้วส่ง frame ซ้ำ ผู้รับต้องไม่ส่งข้อมูลซ้ำให้ชั้นบน แต่ยังตอบ ACK เพื่อให้ผู้ส่งเดินต่อได้ จึงต้องแยก “ได้รับ frame อีกครั้ง” กับ “ส่งมอบข้อมูลให้แอปอีกครั้ง”

ในแบบไม่คิดเวลาส่ง ACK และ processing การใช้ประโยชน์ผู้ส่ง U≈(L/R)/(RTT+L/R) ถ้า L/R=1 ms แต่ RTT=100 ms จะได้ U≈1/101≈0.99% แปลว่าแม้ลิงก์เร็วก็ว่างเกือบตลอดเพราะรอตอบรับ

HDLC และ PPP

HDLC เป็นตัวอย่าง bit-oriented link protocol มีข้อมูล address, control และ FCS ส่วน PPP ใช้เชื่อม point-to-point มีการเจรจาลิงก์และการตั้งค่าที่เกี่ยวข้อง อย่าเหมารวมว่า data link ทุกเทคโนโลยีต้องรับประกันส่งถึงด้วยการส่งซ้ำ เช่น Ethernet พื้นฐานตรวจ frame แล้วอาจทิ้งโดยไม่ส่งซ้ำระดับลิงก์

ลองตอบ: ACK หายจำเป็นต้องแปลว่า data frame หายหรือไม่

เฉลยและเหตุผล: ไม่ ข้อมูลอาจถึงแล้วแต่ข้อความตอบรับหาย จึงต้องใช้ sequence number กรอง duplicate และตอบรับซ้ำได้

ลองตอบ: เลขลำดับ 4 บิตใช้ GBN และ SR ได้ window สูงสุดเท่าไร

เฉลยและเหตุผล: GBN 15 ส่วน SR แบบหน้าต่างเท่ากัน 8 ต้องระบุสมมติฐานของโปรโตคอลด้วย

จำให้ได้: จำเหตุผลของ sequence number, timer, ACK และความต่าง GBN/SR มากกว่าท่องชื่อ

Figure 11.31 shows an exchange in which a frame is lost. Node B sends three data frames (0, 1, and 2), but frame 1 is lost.
