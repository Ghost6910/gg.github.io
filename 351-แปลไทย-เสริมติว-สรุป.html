แปลและเรียบเรียงแนวคิดหลัก

การสื่อสารข้อมูล (Data communications) คือการแลกเปลี่ยนข้อมูลระหว่างอุปกรณ์ผ่านสื่อส่งข้อมูล เช่น สายทองแดง ใยแก้วนำแสง หรือคลื่นวิทยุ คำว่า “ข้อมูล” หมายถึงสิ่งที่ต้องการสื่อ ส่วน “สัญญาณ” คือรูปทางกายภาพที่ใช้ขนข้อมูลนั้น ข้อความเดียวกันอาจส่งด้วยสัญญาณไฟฟ้าบนสาย หรือสัญญาณแสงบนไฟเบอร์ก็ได้

ระบบสื่อสารมี 5 องค์ประกอบ ได้แก่ Message ข้อมูลที่ส่ง, Sender ผู้ส่ง, Receiver ผู้รับ, Transmission medium สื่อกลาง และ Protocol กติกาที่ทั้งสองฝ่ายเข้าใจร่วมกัน การต่อสายติดเพียงอย่างเดียวยังไม่ทำให้สื่อสารได้ หากรูปแบบข้อความหรือขั้นตอนตอบรับไม่ตรงกัน

คุณภาพการสื่อสารพิจารณา Delivery ส่งถึงปลายทางที่ถูกต้อง, Accuracy ข้อมูลถูกต้อง, Timeliness ถึงทันเวลา และ Jitter ความแปรปรวนของเวลาหน่วง เสียงสนทนาอาจยอมเสียข้อมูลบางส่วนได้แต่ไวต่อความล่าช้า ต่างจากไฟล์ที่ต้องครบทุกบิต

Protocol กำหนด Syntax รูปแบบ, Semantics ความหมาย และ Timing ลำดับหรือจังหวะของการแลกเปลี่ยนข้อมูล ส่วน Standard คือข้อกำหนดที่ตกลงร่วมกันเพื่อให้ผู้ผลิตต่างรายทำงานร่วมกันได้ อย่าตอบว่า protocol คือ “โปรแกรม” เพราะกติกาเดียวกันอาจมีการพัฒนาโปรแกรมได้หลายแบบ

ลองตอบ: ถ้าเครื่อง 6 เครื่องต่อ full mesh ต้องใช้กี่ลิงก์

เฉลยและเหตุผล: 6×5/2 = 15 ลิงก์ แต่ละเครื่องต่อ 5 ลิงก์ หาร 2 เพราะลิงก์ A–B กับ B–A คือคู่เดียวกัน

ลองตอบ: ทำไมเปิดไฟล์ได้ครบแต่ประชุมเสียงกระตุก

เฉลยและเหตุผล: ไฟล์มักมีการส่งซ้ำเพื่อให้ครบ ส่วนเสียงไวต่อ delay และ jitter แม้ throughput เฉลี่ยพอ ความหน่วงแปรปรวนก็ทำให้เล่นเสียงไม่ต่อเนื่องได้

Analog data มีค่าต่อเนื่อง เช่น ความดันเสียง ส่วน Digital data มีค่าที่แยกเป็นหน่วย เช่น บิต 0/1 สัญญาณ analog เปลี่ยนค่าต่อเนื่อง และสัญญาณ digital แทนข้อมูลด้วยระดับที่กำหนด ข้อมูล digital ส่งบนคลื่น analog ได้ผ่าน modulation จึงห้ามเหมารวมข้อมูลกับสัญญาณ

คลื่นไซน์อธิบายด้วย Amplitude ขนาดสัญญาณ, Frequency จำนวนรอบต่อวินาที และ Phase ตำแหน่งเทียบเวลา Period คือเวลาต่อรอบ T=1/f หน่วยความถี่เป็น Hz และคาบเป็นวินาที ความยาวคลื่น λ=v/f ขึ้นกับความเร็วการแพร่ในสื่อ v

สัญญาณผสมประกอบด้วยหลายความถี่ Bandwidth ทางความถี่เป็นช่วง fสูง−fต่ำ หน่วย Hz ต่างจากคำว่า bandwidth ที่มักใช้เรียกอัตรารับส่งสูงสุดหน่วย bit/s ในการพูดเรื่องเครือข่าย ต้องอ่านหน่วยทุกครั้ง

Bit rate, baud และหน่วย

Bit rate คือจำนวนบิตต่อวินาที ส่วน Signal rate หรือ baud คือจำนวนสัญลักษณ์ต่อวินาที ถ้าหนึ่งสัญลักษณ์เลือกได้ M สถานะ จะบรรทุก log₂M บิตในแบบจำลองคงที่ จึงได้ Rb = Rs log₂M ตัวอย่าง 16 สถานะ = 4 บิต/สัญลักษณ์ ที่ 2,400 baud ได้ 9,600 bit/s ก่อนหัก overhead

ตัวอย่าง Nyquist และ Shannon

ช่องไร้ noise ตามแบบจำลอง Nyquist มี Rmax = 2B log₂M ถ้า B=3,000 Hz และ M=4 ได้ 12,000 bit/s เป็นขีดจำกัดตามสมมติฐาน ไม่ใช่รับประกันอุปกรณ์จริง

ช่องมี noise ตาม Shannon มี C=B log₂(1+S/N) โดย S/N ต้องเป็นอัตราส่วนเชิงเส้น ถ้า SNR=30 dB ต้องแปลงเป็น 10^(30/10)=1,000 เมื่อ B=3,000 Hz จะได้ C≈29,902 bit/s ไม่ใช่แทน 30 ลงไปโดยตรง

Nyquist ใช้พิจารณาจำนวนระดับและ bandwidth ในช่องอุดมคติ ส่วน Shannon เป็นขีดจำกัดข้อมูลจาก bandwidth กับ SNR ถ้าโจทย์ให้ทั้งคู่ต้องตรวจข้อจำกัดทั้งสอง ไม่เลือกค่ามากกว่าเพียงเพราะดูดีกว่า

ลองตอบ: 64-QAM หนึ่งสัญลักษณ์แทนกี่บิต

Analog-to-digital: PCM

Pulse Code Modulation มี 3 ขั้นคือ Sampling เก็บตัวอย่าง, Quantization ปัดค่าลงระดับ และ Encoding แทนระดับด้วยบิต ภายใต้สัญญาณ baseband ที่จำกัดความถี่สูงสุด fmax ต้องเลือก sampling rate อย่างน้อย 2fmax ตามเกณฑ์ในแบบจำลอง และระบบจริงต้องพิจารณา filter กับระยะเผื่อ

ถ้าระดับ quantization มี L ระดับ ต้องใช้ n=⌈log₂L⌉ บิตต่อตัวอย่าง เมื่อเก็บ 8,000 samples/s และใช้ 8 bits/sample ได้ 64,000 bit/s ต่อช่องก่อน overhead ถ้ามีสองช่องให้คูณสอง

Quantization error เกิดจากการแทนค่าต่อเนื่องด้วยระดับจำกัด เพิ่มจำนวนบิตช่วยลดความผิดพลาดนี้ แต่เพิ่ม bit rate อย่าสับสนกับ sampling error หรือความผิดพลาดของบิตระหว่างส่ง

กลับสารบัญ ↑

วิธีส่ง: Parallel และ Serial

Parallel ส่งหลายบิตพร้อมกันบนหลายเส้น ส่วน Serial ส่งเป็นลำดับบนช่องทางอนุกรม การส่ง parallel ไกลมีปัญหาบิตมาถึงไม่ตรงกัน (skew) จึงสรุปจากจำนวนเส้นอย่างเดียวไม่ได้ว่าเร็วกว่า

Asynchronous serial เช่นรูปแบบ 8N1 ใช้ start 1 บิต + data 8 บิต + stop 1 บิต รวม 10 บิตต่ออักขระ ประสิทธิภาพส่วนข้อมูล 8/10=80% โดยไม่คิดช่องว่าง ถ้าสายส่ง 9,600 bit/s ได้ข้อมูล 7,680 bit/s หรือ 960 อักขระ/วินาที

Synchronous ส่งเป็นกลุ่มหรือ frame และต้องรักษาการประสานเวลา ส่วน Isochronous เน้นการส่งตามจังหวะที่รองรับงานต้องการเวลา ไม่ใช่คำพ้องของ full-duplex

เสริมชุด Network: DTE/DCE และ Interface

DTE เป็นอุปกรณ์ปลายทางข้อมูล เช่นเครื่องคอมพิวเตอร์ ส่วน DCE จัดการการเชื่อมต่อหรือสัญญาณสู่ระบบสื่อสาร เช่นโมเด็ม Interface ระบุได้ทั้งรูปทรงขั้วต่อ (Mechanical), ระดับไฟฟ้า (Electrical), หน้าที่แต่ละขา (Functional) และขั้นตอนใช้สัญญาณ (Procedural)

ใน RS-232 ชื่อ TXD/RXD ต้องอ่านจากมุมอุปกรณ์ที่ระบุ การต่อ null modem ระหว่าง DTE สองตัวต้องไขว้สายส่ง/รับและอาจต้องจัดการ control signals เพิ่มตามแบบ ตัวเลขความเร็วและระยะจากสไลด์เป็นบริบทของมาตรฐาน/อุปกรณ์ในยุคนั้น ไม่ใช่ข้อสรุปครอบคลุม serial ทุกชนิด

ลองตอบ: เสียงจำกัด 4 kHz เก็บที่ 8 ksample/s 256 ระดับ ได้กี่ bit/s

เฉลยและเหตุผล: 256 ระดับใช้ 8 บิต จึงได้ 8,000×8=64,000 bit/s และ sampling rate เท่ากับ 2×4,000 ในแบบจำลอง

ลองตอบ: 8N1 ส่งข้อมูล 100 byte ต้องส่งกี่บิต

เฉลยและเหตุผล: 100×(1+8+1)=1,000 บิต โดยไม่รวมช่วงว่างหรือ protocol อื่น

จำให้ได้: แยก line coding / block coding / scrambling และจำ PCM: sampling → quantization → encoding

Digital-to-analog conversion คือใช้ข้อมูลดิจิทัลควบคุมคุณลักษณะของคลื่นพาหะ Carrier เป็นคลื่นที่ถูกปรับ ไม่ใช่ข้อมูลปลายทางโดยตัวมันเอง ASK เปลี่ยน amplitude, FSK เปลี่ยน frequency, PSK เปลี่ยน phase และ QAM เปลี่ยน amplitude กับ phase ร่วมกัน

ตัวอย่างคำนวณ

ถ้าต้องการ 24,000 bit/s ด้วย 16-QAM ซึ่งมี 4 บิตต่อสัญลักษณ์ ต้องใช้ symbol rate 24,000/4=6,000 baud ถ้าเป็น 64-QAM ใช้ 6 บิตต่อสัญลักษณ์ จะเหลือ 4,000 baud ภายใต้สมมติฐานเดียวกัน การลด baud ไม่ได้แปลว่าไม่ต้องคำนึงถึง SNR

Analog-to-analog

AM เปลี่ยน amplitude ของพาหะด้วยข้อมูล analog; FM เปลี่ยนความถี่ทันที; PM เปลี่ยนเฟส รูปสัญญาณ AM จึงเห็นซองคลื่นตามข้อมูล ส่วน FM เปลี่ยนระยะห่างระหว่างรอบ การถามว่า “เสียงเป็น analog แล้วทำไมต้อง modulation” ตอบว่าต้องเลื่อนสเปกตรัมไปยังย่านที่เหมาะกับสื่อและการแบ่งช่อง

ลองตอบ: ข้อมูล 12 kb/s ส่งด้วย 8-PSK ต้องใช้กี่ baud

เฉลยและเหตุผล: log₂8=3 จึงได้ 12,000/3=4,000 baud โดยยังไม่รวม overhead จากการเข้ารหัสอื่น

ลองตอบ: QAM เพิ่มจำนวนจุดแล้วเร็วขึ้นฟรีหรือไม่

เฉลยและเหตุผล: ไม่ฟรี จุดอยู่ใกล้กันขึ้นเมื่อกำลังส่งเท่าเดิม จึงแยกผิดง่ายขึ้นเมื่อมี noise ต้องแลกกับ SNR หรือความซับซ้อนระบบ

จำให้ได้: จำสิ่งที่ถูกปรับใน ASK/FSK/PSK/QAM และใช้ bit rate = baud × bits/symbol

Synchronous กับ Statistical TDM

Synchronous TDM จัดช่องเวลาแน่นอนให้แต่ละแหล่ง แม้แหล่งนั้นไม่มีข้อมูล slot ก็อาจว่าง Statistical TDM จัด slot ให้แหล่งที่มีข้อมูล จึงต้องมีการระบุช่องหรือที่อยู่และมี buffer รองรับโหลดที่ไม่สม่ำเสมอ

ตัวอย่าง 4 ช่อง ช่องละ 1 kb/s รวมแบบ bit interleaving โดยไม่คิด overhead ต้องส่ง 4 kb/s หนึ่ง frame มี 4 บิต ส่ง 1,000 frame/s ถ้าเพิ่ม framing bit อีก 1 บิตต่อ frame จะต้องใช้ 5 kb/s และประสิทธิภาพข้อมูลเป็น 4/5=80%

อย่าสับสน “frame ของ TDM” กับ Ethernet frame ทั้งคู่เป็นกลุ่มข้อมูลแต่มีโครงสร้างและบริบทคนละแบบ ข้อสอบที่ให้จำนวน slot, ขนาด slot และ frame rate ให้คูณสามตัวนี้เพื่อหาอัตราส่งรวม

Spread spectrum

FHSS กระโดดความถี่พาหะตามลำดับที่ผู้ส่งและผู้รับตกลงกัน DSSS คูณหรือรวมข้อมูลกับลำดับ chip ที่เร็วกว่า bit rate อัตรา chip มากกว่า bit ทำให้สัญญาณกระจายกว้างขึ้น ผู้รับใช้ลำดับที่ตรงกันในการกู้ข้อมูล

การใช้ spreading code ไม่เท่ากับการเข้ารหัสลับแบบ cryptography โดยอัตโนมัติ ต้องแยกคุณสมบัติการกระจายสเปกตรัมออกจากการรับรองความลับของข้อมูล

ลองตอบ: 8 ช่อง ช่องละ 8 bit ต่อ frame ส่ง 1,000 frame/s มี framing 1 bit/frame ได้เท่าไร

เฉลยและเหตุผล: (8×8+1)×1,000=65,000 bit/s ข้อมูลจริง 64,000 bit/s

ลองตอบ: เหตุใด statistical TDM ยังเกิดคิวได้

เฉลยและเหตุผล: เพราะผลรวมอัตราข้อมูลขณะหนึ่งอาจเกินอัตราลิงก์ แม้อัตราเฉลี่ยระยะยาวจะเหมาะสม จึงต้องรอใน buffer

จำให้ได้: FDM แบ่งความถี่, WDM แบ่งความยาวคลื่น, TDM แบ่งเวลา; ระวัง overhead ต่อ frame

Fiber optic

ใยแก้วใช้แสงเดินทางใน core ที่หุ้มด้วย cladding Multimode รองรับหลายเส้นทางการแพร่ ทำให้มี modal dispersion; Single-mode ลดปัญหานี้และเหมาะกับระยะไกล การออกแบบจริงต้องดูชนิดแสง ความยาวคลื่น transceiver และงบกำลังแสง

คลื่นวิทยุและเส้นทางการแพร่

Radio, Microwave และ Infrared ต่างกันที่ย่านความถี่ การทะลุผ่านสิ่งกีดขวาง ทิศทาง และอุปกรณ์ที่ใช้ หลายระบบ microwave ต้องคำนึง line-of-sight ส่วน infrared ไม่ผ่านผนังทึบได้เหมือนคลื่นบางย่าน

เสริมติวเลือกสื่อ

แปลและเรียบเรียงวิธีสวิตช์

Circuit switching จัดสรรทรัพยากรให้การสื่อสารก่อนส่งข้อมูล โดยมีขั้นตั้งวงจร ส่ง และยุติ วงจรอาจเป็น slot หรือย่านความถี่ ไม่จำเป็นต้องเป็นสายโลหะเฉพาะที่เชื่อมตรงทั้งเส้น

Packet switching แบ่งข้อมูลเป็น packet แล้วใช้ทรัพยากรร่วมกันตามเวลาที่มีข้อมูล Datagram network ตัดสินเส้นทาง packet แต่ละตัว ส่วน Virtual-circuit network มีการตั้งสถานะเส้นทางและใช้ป้ายระบุวงจรเสมือนก่อนส่งข้อมูล

Message switching เก็บทั้งข้อความก่อนส่งต่อ ทำให้แต่ละโหนดต้องรองรับข้อความขนาดใหญ่ Packet switching แบ่งหน่วยให้เล็กลงจึงส่งแบบ pipeline ได้

Store-and-forward และเวลา

Store-and-forward ต้องรับ packet ทั้งก้อนก่อนเริ่มส่งก้อนนั้นบนลิงก์ถัดไป สมมติ packet L บิต ผ่าน N ลิงก์อัตรา R เท่ากันและไม่คิด propagation/queue/processing เวลา packet เดียวเท่ากับ NL/R

ตัวอย่าง L=8,000 บิต, R=1 Mb/s, 3 ลิงก์ ได้ 3×0.008=24 ms ถ้าส่ง P packet ต่อเนื่องบนเส้นที่อัตราเท่ากัน ในแบบจำลอง pipeline เวลาจบทั้งหมด=(N+P−1)L/R ไม่ใช่ NP L/R เพราะ packet คนละตัวอยู่คนละลิงก์พร้อมกันได้

Telephone network แบบดั้งเดิมมี local loop เชื่อมผู้ใช้กับชุมสาย และ trunk เชื่อมชุมสาย ระบบที่สไลด์อธิบายใช้ circuit switching เป็นพื้นฐานของบริการเสียง โมเด็มแปลงข้อมูลให้ผ่านช่องเสียงได้ ส่วน DSL ใช้ย่านความถี่บนคู่สายโทรศัพท์กว้างกว่าช่องเสียง

ADSL แบ่งย่านสำหรับเสียง upstream และ downstream โดยจัดความจุไม่เท่ากัน เหมาะกับรูปแบบใช้งานที่ดาวน์โหลดมากกว่าอัปโหลด Splitter แยกเสียงกับ DSL ฝั่งผู้ใช้ และ DSLAM รวมการเชื่อมต่อ DSL ที่ฝั่งผู้ให้บริการ

Cable network ใช้โครงสร้าง Hybrid Fiber-Coaxial หรือ HFC มี fiber ในส่วนโครงข่ายและ coax ไปยังกลุ่มผู้ใช้ Cable modem ฝั่งบ้านสื่อสารกับอุปกรณ์ส่วนกลาง เช่น CMTS การแชร์ช่องในบริเวณหนึ่งทำให้ throughput ขึ้นกับโหลดและการจัดสรรทรัพยากร

เสริมติว: Dedicated กับ Shared

สายช่วงบ้านถึงชุมสายของ DSL อาจเป็นคู่สายเฉพาะผู้ใช้ แต่เส้นทางส่วนอื่นและ Internet ยังมีทรัพยากรร่วมกัน จึงไม่ควรสรุปว่า DSL ได้ความเร็วคงที่ตลอดเส้น ส่วน cable ที่แชร์สื่อก็ไม่ได้หมายความว่าความเร็วจะหารจำนวนบ้านแบบตายตัวตลอดเวลา

ตัวเลขอัตราส่งของโมเด็ม DSL หรือ cable ในเอกสารเป็นตัวอย่างยุคต้นฉบับ การทำข้อสอบจากสไลด์ให้ใช้ค่าที่โจทย์ระบุ ส่วนหลักการสำคัญคือการแบ่งความถี่ โครงข่ายเข้าถึง และจุดที่มีการใช้ทรัพยากรร่วมกัน

ลองตอบ: เหตุใด ADSL โทรศัพท์และข้อมูลทำงานพร้อมกันได้

เฉลยและเหตุผล: เพราะแบ่งสัญญาณไปอยู่คนละย่านความถี่และมีอุปกรณ์แยกย่าน ไม่ได้ให้ข้อมูลกับเสียงแย่งใช้ช่องเสียงเดียวกันแบบโมเด็ม dial-up

ลองตอบ: ความเร็วแพ็กเกจเท่ากับ throughput จริงหรือไม่

เฉลยและเหตุผล: ไม่เสมอ ต้องหัก overhead และพิจารณาโหลด สภาพสาย เส้นทาง และคอขวดอื่น

จำให้ได้: จำ local loop / DSLAM / HFC / cable modem และแยกความจุ access link จากความเร็วทั้งเส้นทาง

แปลและเรียบเรียงหลักการ

Single-bit error คือเปลี่ยนค่าหนึ่งบิต ส่วน Burst error มีความผิดพลาดกระจายอยู่ในช่วงหนึ่ง โดยความยาว burst นับจากบิตผิดแรกถึงบิตผิดสุดท้าย ไม่ได้แปลว่าทุกบิตระหว่างนั้นผิดทั้งหมด

Redundancy คือเพิ่มข้อมูลที่มีความสัมพันธ์กับข้อมูลจริง เพื่อให้ผู้รับตรวจหรือแก้ข้อผิดพลาดได้ Error detection บอกว่าพบความผิดปกติ ส่วน Error correction ต้องมีข้อมูลพอระบุค่าที่ถูกต้องหรืออาศัยการส่งซ้ำ การมี checksum ไม่ได้แปลว่าแก้ข้อมูลได้เอง

Hamming distance และ Parity

Hamming distance คือจำนวนตำแหน่งบิตที่ต่างกันระหว่าง codeword สองคำ ถ้าระยะต่ำสุดของโค้ดคือ dmin จะรับประกันตรวจได้ถึง dmin−1 บิตผิด และแก้ได้ถึง ⌊(dmin−1)/2⌋ บิต ตัวอย่าง dmin=3 ตรวจได้ 2 และแก้ได้ 1

Even parity เพิ่มบิตให้จำนวน 1 รวมเป็นเลขคู่ เช่นข้อมูล 1011001 มี 1 สี่ตัว จึงเพิ่ม 0 ถ้ามีบิตเปลี่ยนจำนวนคี่จะตรวจพบ แต่ถ้าเปลี่ยนจำนวนคู่บางรูปแบบจะไม่พบ Two-dimensional parity เพิ่มการตรวจตามแถวและคอลัมน์ ช่วยระบุตำแหน่งผิดหนึ่งบิตได้ตามโครงสร้าง

สำหรับ Hamming code แก้บิตผิดหนึ่งบิต จำนวน parity bits r ต้องพอให้ 2^r ≥ m+r+1 เมื่อข้อมูล m=4 ใช้ r=3 เพราะ 8≥8 แต่สมการนี้อย่างเดียวไม่ได้บอกตำแหน่ง parity ต้องวางตามรหัสที่ออกแบบ

CRC แบบค่อยเป็นค่อยไป

Cyclic Redundancy Check มองบิตเป็นพหุนามเหนือ GF(2) ใช้ XOR แทนการลบ ผู้ส่งเติมศูนย์ r บิตเมื่อ generator มี degree r แล้วหารเอาเศษ r บิตมาแทนท้ายข้อมูล ผู้รับหาร codeword ด้วย generator เดียวกัน หากเศษไม่เป็นศูนย์แสดงว่าตรวจพบข้อผิดพลาด

ตัวอย่าง D=1101, G=1011 ซึ่งมี degree 3: เติมศูนย์เป็น 1101000 แล้วหาร XOR ได้เศษ 001 จึงส่ง 1101001 เมื่อนำ 1101001 หารด้วย 1011 ได้เศษ 000 ให้ลองเขียนการหารทีละขั้นเพื่อเห็นว่าห้ามใช้การลบที่มีการยืมแบบเลขฐานสองทั่วไป

เศษศูนย์หมายถึง “ไม่ตรวจพบ” ไม่ใช่หลักฐานว่าไม่มีข้อผิดพลาดทุกชนิด ความสามารถตรวจขึ้นกับ generator และรูปแบบ error โค้ดที่ดีรับประกันบางกลุ่ม แต่ยังมี error pattern ที่เป็นพหุคูณ generator แล้วหลุดได้

แบ่งข้อมูลเป็นคำ 16 บิต บวกแบบ one's complement โดยนำ carry สูงสุดวนกลับมาบวกด้านล่าง จากนั้นกลับบิตผลรวมเป็น checksum ผู้รับรวมข้อมูลกับ checksum ถ้าได้บิต 1 ทั้งหมดตามแบบจำลองถือว่าผ่านการตรวจ ไม่ใช่บวกธรรมดาแล้วทิ้ง carry

ลองตอบ: โค้ดที่ dmin=5 ตรวจและแก้ผิดได้เท่าไร

ลองตอบ: CRC ผ่านแล้วรับประกันข้อมูลแท้จากผู้ส่งหรือไม่

เฉลยและเหตุผล: ไม่ CRC ตรวจความผิดพลาดจากสัญญาณตามแบบโค้ด ไม่ได้ยืนยันตัวตนหรือป้องกันผู้โจมตีแก้ข้อมูลแล้วคำนวณ CRC ใหม่

จำให้ได้: Parity / CRC / Checksum ใช้ตรวจผิด; แยกจากการยืนยันความถูกต้องเชิงความปลอดภัยด้วย MAC หรือลายเซ็น

แปลและเรียบเรียง Framing

Data link control ต้องกำหนดขอบเขต frame ควบคุมการไหล และจัดการข้อผิดพลาด Character-oriented framing ใช้ byte พิเศษคั่นและทำ byte stuffing เมื่อข้อมูลมีค่าเหมือนตัวคั่น ส่วน Bit-oriented framing ใช้รูปแบบบิตคั่นและ bit stuffing เพื่อไม่ให้ข้อมูลปลอมเป็นขอบเขต

ตัวอย่างแนว HDLC ใช้ flag 01111110 ผู้ส่งแทรก 0 หลังเจอ 1 ติดต่อกันห้าบิตในเนื้อหาที่ต้องทำ stuffing ผู้รับตัด 0 ที่แทรกออกตามกติกา การเพิ่มบิตนี้ต่างจากการเพิ่มบิต parity เพราะจุดประสงค์คือรักษาขอบเขต ไม่ใช่สร้างโค้ดตรวจผิด

Stop-and-Wait และ ARQ

Stop-and-Wait ส่งหนึ่ง frame แล้วรอ ACK ก่อนส่งต่อ ARQ รวมการตรวจข้อผิดพลาด เลขลำดับ การตอบรับ และ timer เพื่อส่งซ้ำเมื่อจำเป็น เลขลำดับช่วยแยกข้อมูลใหม่กับข้อมูลเดิมที่ส่งซ้ำเมื่อ ACK หาย

ถ้า ACK หาย ผู้ส่ง timeout แล้วส่ง frame ซ้ำ ผู้รับต้องไม่ส่งข้อมูลซ้ำให้ชั้นบน แต่ยังตอบ ACK เพื่อให้ผู้ส่งเดินต่อได้ จึงต้องแยก “ได้รับ frame อีกครั้ง” กับ “ส่งมอบข้อมูลให้แอปอีกครั้ง”

ในแบบไม่คิดเวลาส่ง ACK และ processing การใช้ประโยชน์ผู้ส่ง U≈(L/R)/(RTT+L/R) ถ้า L/R=1 ms แต่ RTT=100 ms จะได้ U≈1/101≈0.99% แปลว่าแม้ลิงก์เร็วก็ว่างเกือบตลอดเพราะรอตอบรับ

Ethernet เป็นตระกูลเทคโนโลยี LAN ที่เกี่ยวข้องกับ IEEE 802.3 ครอบคลุมส่วน MAC และ physical หลายรูปแบบ โครงสร้างกายภาพอาจเป็น bus ในระบบเก่า หรือ star ต่อ switch ในระบบที่เรียนกันทั่วไป ต้องแยก topology ทางกายภาพจากวิธีใช้ช่องร่วมกัน

โครงสร้าง Frame

Ethernet II มี destination MAC, source MAC, EtherType, payload/padding และ FCS ส่วน preamble/SFD ใช้ประสานและเริ่ม frame ในการนับขนาดต้องอ่านว่ารวมส่วนใด กรอบพื้นฐานแบบไม่ติด VLAN มี 64–1518 bytes จาก destination MAC ถึง FCS ไม่รวม preamble/SFD และ inter-frame gap

Payload พื้นฐานอยู่ในช่วง 46–1500 bytes หากข้อมูลสั้นต้องเติม padding ให้ถึงขนาดขั้นต่ำ FCS ใช้ตรวจความผิดพลาดและ frame ที่ผิดจะถูกทิ้ง แต่ Ethernet ไม่ให้ ACK และ retransmission แบบ TCP

Repeater ทำสัญญาณใหม่ระดับ physical; Hub เป็น repeater หลายพอร์ต; Bridge/Switch ส่งต่อ frame โดย MAC; Router ส่งต่อ packet ตาม IP และเส้นทาง ส่วน Gateway เป็นคำกว้าง ต้องอ่านบริบทว่าหมายถึง router ประตูออกหรืออุปกรณ์แปลงบริการ

VLAN และ Trunk

VLAN แบ่งเครือข่ายชั้น 2 เชิงตรรกะให้พอร์ตคนละกลุ่มอยู่คนละ broadcast domain แม้ใช้ switch ตัวเดียวกัน การสื่อสารข้าม VLAN ต้องมีการ route ผ่าน router หรืออุปกรณ์ชั้น 3 และใช้ addressing ที่เหมาะสม

Access port ส่ง traffic ของ VLAN เดียวให้เครื่องปลายทางในรูปแบบปกติ ส่วน trunk ขน traffic หลาย VLAN บนลิงก์เดียวด้วยการระบุ VLAN เช่น 802.1Q ต้องตั้ง VLAN ที่อนุญาตและการตีความ untagged/native ให้สอดคล้องตามระบบ

Backbone เป็นส่วนเชื่อมเครือข่ายย่อยเข้าด้วยกัน อาจออกแบบเป็น bus, star หรือหลายระดับ การรวมศูนย์ช่วยดูแลแต่ต้องคำนึงจุดล้มเหลวและความจุ uplink

ลองตอบ: สวิตช์รู้ MAC ปลายทางได้อย่างไร

เฉลยและเหตุผล: เรียนรู้จาก source MAC ของ frame ที่เคยเข้ามา ไม่ได้ถาม DNS และไม่ได้อ่าน routing table เพื่อเรียนรู้ MAC

ลองตอบ: เครื่องต่าง VLAN แต่ IP subnet เดียวกันจะคุยกันได้เองหรือไม่

เฉลยและเหตุผล: โดยทั่วไปไม่ เพราะ ARP broadcast ไม่ข้าม VLAN การกำหนด subnet เดียวกันข้ามโดเมนชั้น 2 ทำให้การเข้าถึงผิดจากสมมติฐานปกติ ต้องออกแบบและ route ให้ถูก

จำให้ได้: Switch เรียน source → เลือกด้วย destination; VLAN แยก broadcast, router เชื่อมข้ามเครือข่าย

แปลและเรียบเรียง Cellular

Cellular แบ่งพื้นที่ให้บริการเป็น cell มีสถานีฐานดูแลและใช้ความถี่ซ้ำเมื่อระยะ/การรบกวนเหมาะสม ความจุเพิ่มด้วยการใช้ทรัพยากรซ้ำเชิงพื้นที่ ไม่ใช่เพิ่มกำลังสถานีฐานอย่างเดียว

Handoff หรือ handover เปลี่ยนจุดให้บริการเมื่อผู้ใช้เคลื่อนที่ ต้องจัดการการต่อเนื่องของการสื่อสาร ส่วน Roaming คือการใช้บริการนอกขอบเขตเครือข่ายต้นสังกัดตามระบบและข้อตกลง ทั้งสองไม่ใช่คำเดียวกัน

สไลด์เปรียบเทียบยุคระบบตั้งแต่ analog ไปสู่ digital และวิธีแบ่งช่อง เช่น FDMA/TDMA/CDMA ให้เน้นหลักการที่ต่างกัน ตัวเลขในสไลด์เป็นบริบทเทคโนโลยีของเอกสาร ไม่ใช้เป็นรายการเครือข่ายโทรศัพท์ล่าสุด

ดาวเทียม

GEO, MEO และ LEO แบ่งตามระดับวงโคจรโดยทั่วไป GEO มีวงโคจรที่เหมาะกับการปรากฏอยู่ตำแหน่งเดิมเมื่อมองจากพื้นโลกตามเงื่อนไขวงโคจร แต่ไกลจึงมี propagation delay สูง LEO ใกล้กว่าแต่ดาวเคลื่อนที่เมื่อเทียบผู้ใช้ จึงต้องจัดการการติดตามและการเปลี่ยนดาวที่ให้บริการ

ถ้าประมาณระยะทางจากพื้นสู่ GEO ที่ราว 35,786 km แล้วลงอีกฝั่ง ระยะหนึ่งทางผ่านดาวประมาณ 71,572 km หาร c≈300,000 km/s ได้ราว 0.239 s; RTT อย่างน้อยราว 0.477 s ก่อนคิดเส้นทางจริงและ processing การหารแค่ความสูงครั้งเดียวทำให้ตอบต่ำกว่าความจริง

ลองตอบ: เหตุใด GEO latency สูงแม้มี bandwidth มาก

เฉลยและเหตุผล: Bandwidth เพิ่มอัตราผลักข้อมูล แต่ไม่ทำให้สัญญาณเดินทางระยะไกลเร็วกว่าแสง Delay จากระยะทางยังอยู่

ลองตอบ: Frequency reuse เกี่ยวข้องกับ cell อย่างไร

เฉลยและเหตุผล: กลุ่ม cell ที่ห่างเหมาะสมใช้ทรัพยากรความถี่ซ้ำได้โดยควบคุมการรบกวน ทำให้รองรับผู้ใช้เพิ่มเชิงพื้นที่

จำให้ได้: แยก handoff/roaming และแยกความจุลิงก์ออกจาก propagation delay

Frame และตัวอย่างอัตรา

STS-1 มีกรอบ 9 แถว × 90 คอลัมน์ แต่ละช่อง 1 byte รวม 810 bytes ส่ง 8,000 frame/s จึงมีอัตรา 810×8×8,000=51.84 Mb/s นี่คืออัตรารวมก่อนหัก overhead ไม่ใช่ payload ของผู้ใช้ทั้งหมด

ส่วน overhead ให้ข้อมูลบริหารและควบคุมหลายระดับ เช่น section, line และ path ส่วน pointer ช่วยบอกตำแหน่ง payload envelope เมื่อจังหวะ/ตำแหน่งสัมพันธ์กันเปลี่ยนในโครงข่าย synchronous

Protection และข้อคิด

โครงข่าย ring จัดเส้นทางสำรองและสลับเมื่อเสียได้ตามกลไก protection ที่ใช้ แต่การมีรูปวงไม่ได้รับประกันว่าไม่ล่ม ต้องดูจำนวนจุดเสีย อุปกรณ์และการออกแบบการป้องกัน

ลองตอบ: STS-1 ทำไมเป็น 51.84 Mb/s

เฉลยและเหตุผล: 9×90 bytes/frame ×8 bits/byte ×8,000 frame/s =51,840,000 bit/s ระวังลืมคูณ 8

ลองตอบ: 51.84 Mb/s เป็นข้อมูลแอปล้วนหรือไม่

แปลและเรียบเรียง Virtual-Circuit WAN

Frame Relay เป็นเครือข่าย WAN แบบวงจรเสมือนที่ใช้ frame ขนาดแปรผัน สไลด์ใช้ DLCI เป็นตัวระบุวงจรบนลิงก์หนึ่ง ค่า DLCI มีความหมายเฉพาะบริบท ไม่ต้องมีเลขเดียวกันตลอดเส้นทางต้นทางถึงปลายทาง

ATM ใช้ cell ขนาดคงที่ 53 bytes แบ่ง header 5 bytes และ payload 48 bytes ขนาดคงที่ช่วยให้สวิตช์และการจัดตารางทำงานเป็นหน่วยสม่ำเสมอ แต่มี overhead เมื่อขนข้อมูลหรือข้อมูลท้ายไม่เต็ม cell

ตัวระบุและชั้นย่อย

VPI ระบุ virtual path และ VCI ระบุ virtual channel ตามโครงสร้าง ATM การสวิตช์อาศัยบริบท interface กับตัวระบุ แล้วแปลเป็นตัวระบุขาออก ไม่ใช่เอา VCI ไปตีความเป็น IP address

AAL หรือ ATM Adaptation Layer ช่วยปรับข้อมูลของบริการด้านบนให้เข้ารูป cell มีการแบ่งและประกอบกลับที่เรียก SAR (Segmentation and Reassembly) จึงต้องแยก packet ของแอปจาก ATM cell

ตัวอย่าง overhead

ถ้าคิดเฉพาะ header ของ cell ประสิทธิภาพสูงสุดส่วน payload=48/53≈90.57% ก่อน overhead ของ AAL หรือการเติมท้าย หากต้องส่งข้อมูล 100 bytes และยังไม่คิด AAL ต้องใช้ ⌈100/48⌉=3 cells รวม 159 bytes ประสิทธิภาพข้อมูลจริง 100/159≈62.89%

เอกสารส่วนนี้อธิบายเทคโนโลยีและแนวคิดวงจรเสมือนของยุคต้นฉบับ จุดที่นำไปเชื่อมบทอื่นคือ label switching, QoS และข้อแลกเปลี่ยนหน่วยข้อมูลขนาดคงที่กับแปรผัน

ลองตอบ: ATM cell 53 bytes หมายถึงข้อมูลผู้ใช้ 53 bytes หรือไม่

เฉลยและเหตุผล: ไม่ มี header 5 bytes จึงเหลือ payload 48 bytes และ payload บางส่วนอาจเป็น overhead ของ AAL

ลองตอบ: DLCI ต้องเท่ากันทุกลิงก์หรือไม่

เฉลยและเหตุผล: ไม่ ตัวระบุวงจรอาจมีความหมายเฉพาะลิงก์และถูกแปลเมื่อผ่านสวิตช์

จำให้ได้: Frame Relay ใช้ frame แปรผัน; ATM ใช้ 53-byte cell; คำนวณจำนวน cell ต้องปัดขึ้น

Fragmentation แบบละเอียด

MTU เป็นขนาด packet ชั้นที่กำหนดซึ่งลิงก์รองรับ หาก IPv4 datagram ใหญ่เกินและอนุญาต fragmentation อาจแบ่งเป็น fragments โดยแต่ละ fragment มี IP header ของตนเอง และนำไปประกอบกลับที่ปลายทาง

ตัวอย่าง IPv4 total length 4,000 bytes, header 20, MTU 1,500: payload เดิม 3,980; แต่ละชิ้นที่ไม่ใช่สุดท้ายบรรทุกได้ 1,480 ซึ่งหาร 8 ลงตัว ได้ชิ้น payload 1,480, 1,480 และ 1,020 รวมความยาว 1,500, 1,500, 1,040 bytes; offsets =0,185,370 และ MF=1,1,0

Fragment offset นับหน่วย 8 bytes ไม่ใช่ byte จึงได้ 1,480/8=185 Header ของแต่ละชิ้นเพิ่ม overhead และถ้าชิ้นใดหาย datagram เดิมอาจประกอบไม่สำเร็จ การแบ่งระดับ TCP เป็น segment ก่อนส่งกับ IP fragmentation เป็นคนละขั้น

TTL, ICMP และ NAT

TTL ลดลงเมื่อผ่าน router หากหมดจะทิ้งและอาจส่ง ICMP แจ้งช่วยหยุด packet วนลูป ไม่ใช่ตัวจับเวลาวินาทีตามการลดค่าจริงใน forwarding ทั่วไป Traceroute ใช้การหมดอายุแบบนี้เพื่อสืบเส้นทางในแบบที่สไลด์อธิบาย

NAT แปลที่อยู่ ส่วน NAPT/PAT แปลทั้ง IP กับ port ทำให้หลายการเชื่อมต่อภายในแชร์ที่อยู่ภายนอกได้ โดยเก็บ mapping เช่น 10.0.0.2:50000 ↔ external:62001 NAT ไม่เท่ากับ firewall แม้อุปกรณ์หนึ่งมักทำทั้งสองหน้าที่

IPv6 กับการเปลี่ยนผ่าน

Link State: Dijkstra

Link-state ให้โหนดมีภาพ topology กับ cost แล้วคำนวณเส้นทางสั้นที่สุดจากตัวเอง Dijkstra เริ่มกำหนด distance ของต้นทางเป็น 0 จากนั้นเลือกโหนดที่ยังไม่ยืนยันซึ่งมี distance ต่ำสุด และ relax ระยะไปเพื่อนบ้าน ทำซ้ำจนยืนยันโหนดที่ต้องการ

ตัวอย่าง A–B=2, A–C=5, B–C=1, B–D=4, C–D=1: เริ่ม B=2,C=5,D=∞; เลือก B แล้วปรับ C=3,D=6; เลือก C แล้วปรับ D=4; จบเส้น A→B→C→D cost 4 ตารางแต่ละรอบต้องจด predecessor เพื่อย้อนหาเส้นจริง

Distance Vector: Bellman-Ford

DV ใช้ Dₓ(y)=minᵥ{c(x,v)+Dᵥ(y)} โดย v เป็นเพื่อนบ้าน เลือกต้นทุนไปเพื่อน v บวกค่าที่ v โฆษณาว่าไป y ได้ แล้วเอาต่ำสุด ไม่จำเป็นต้องรู้ทั้ง topology แบบ LS

เมื่อข่าวลิงก์เสียแพร่ช้า อาจเกิด routing loop และ count-to-infinity กลไกเช่น split horizon หรือ poisoned reverse ช่วยบางกรณีแต่ไม่ได้แก้ loop ทุก topology ทั้งหมด

แปลและเรียบเรียง Process-to-process

Transport เชื่อมการสื่อสารระหว่าง process ต่างจาก network layer ที่ขน packet ระหว่าง host/interface Port ระบุปลายทาง transport ส่วน socket เป็นจุดเชื่อมที่โปรแกรมใช้ส่งรับข้อมูล TCP connection ในแบบพื้นฐานแยกด้วย source IP/port และ destination IP/port

UDP มี header 8 bytes ได้แก่ source port, destination port, length และ checksum ไม่มีการตั้ง connection ไม่มี reliability หรือ congestion control ที่ UDP จัดให้เอง แอปเลือกเพิ่มกลไกเองได้ จึงไม่ควรอธิบายว่าแอปบน UDP ทำ reliability ไม่ได้

TCP เป็น byte stream ที่เชื่อถือได้และเรียงลำดับ ไม่รักษาขอบเขตข้อความแอป เช่นส่งสองครั้งไม่ได้รับประกันว่าปลายทาง recv จะได้สองก้อนเท่ากัน แอปต้องจัด framing ของข้อความเอง

TCP sequence และ ACK แบบละเอียด

TCP sequence number ระบุหมายเลข byte ไม่ใช่หมายเลข segment สมมติ segment เริ่ม Seq=1000 มี payload 200 bytes ครอบคลุม 1000–1199 ถ้าผู้รับได้ครบต่อเนื่องจะตอบ ACK=1200 ซึ่งหมายถึงคาดหวัง byte ถัดไป

Cumulative ACK หมายถึงยืนยัน byte ก่อนหน้าอย่างต่อเนื่อง ถ้าขาดช่วง แม้มีข้อมูลถัดไปถึงแล้ว ACK อาจยังชี้ byte แรกที่ขาด การส่งซ้ำมี timer และ fast retransmit ตามกลไกที่ใช้ Checksum ตรวจผิดไม่ได้ทำหน้าที่แทน sequence หรือ timer

การเปิดและปิด Connection

Three-way handshake: Client ส่ง SYN Seq=x; Server ตอบ SYN+ACK Seq=y, ACK=x+1; Client ตอบ ACK=y+1 เพราะ SYN ใช้หนึ่ง sequence number ช่วยให้สองฝ่ายตกลงเลขเริ่มต้นและรับรู้การสื่อสารสองทาง

การปิดแต่ละทิศใช้ FIN ซึ่งใช้หนึ่ง sequence number เช่นกัน TCP full-duplex จึงอาจปิดการส่งฝั่งหนึ่งก่อนอีกฝั่ง FIN กับ RST ทำหน้าที่ต่างกัน และ state เช่น TIME_WAIT มีเหตุผลด้านข้อมูลเก่าและการตอบรับท้าย

rwnd คือพื้นที่รับที่ผู้รับประกาศเพื่อไม่ให้ buffer ฝั่งรับล้น ส่วน cwnd จำกัดข้อมูลค้างบนเครือข่ายเพื่อคุม congestion ข้อมูลที่ส่งค้างได้ถูกจำกัดทั้งสองด้าน ในแบบพื้นฐานต้องอยู่ภายใต้ min(rwnd,cwnd) หักข้อมูลที่ส่งไปแล้วยังไม่ ACK

SCTP ที่สไลด์แนะนำเป็น transport แบบ message-oriented มีแนวคิด multistreaming และ multihoming จึงแยกจาก TCP byte stream อย่านำคำว่า multi-stream มาอธิบายว่า TCP รักษาขอบเขตข้อความได้

QoS: ต้องการรับรองอะไร

คุณสมบัติที่พิจารณาได้แก่ bandwidth/throughput, delay, jitter และ loss แอปแต่ละชนิดไวต่างกัน การรับรอง QoS ต้องดูทั้งการจำแนก traffic การจัดคิว การกำหนดอัตราและการควบคุมการรับ flow ไม่ใช่เพิ่ม priority ทุก packet แล้วดีพร้อมกัน

กลไกหลักการผลที่ต้องเข้าใจ
FIFOเข้าก่อนออกก่อนง่าย แต่ traffic ไวต่อเวลารอหลังงานใหญ่ได้
Priority queueบริการลำดับสูงก่อนต้องคุม starvation ของลำดับต่ำ
Weighted fair queuingแบ่งบริการตามน้ำหนักช่วยจัดส่วนแบ่งตามคลาส
Leaky bucketระบายตามอัตราที่กำหนดทำให้ traffic เรียบขึ้น
Token bucketสะสมสิทธิ์ส่งได้ถึงขนาด bucketรองรับ burst ภายใต้ค่าเฉลี่ยที่กำหนด

IntServ/RSVP ในสไลด์เน้นการจองสำหรับ flow ส่วน DiffServ จัดบริการเป็นกลุ่ม/คลาส มีข้อแลกเปลี่ยนสถานะและการขยายระบบ ค่า DSCP มีประโยชน์เมื่ออุปกรณ์ตามเส้นทางมีนโยบายรองรับ ไม่ใช่ใส่เลขแล้วรับประกันทันที

FTP

FTP แบบดั้งเดิมแยก control connection จาก data connection Control โดยทั่วไปใช้ TCP 21 ส่วน data ขึ้นกับ active/passive mode Active ให้ server เริ่ม data connection ไป client; Passive ให้ client เชื่อมไป port ที่ server แจ้ง จึงมีผลเมื่อผ่าน NAT/firewall

คำตอบว่า FTP ใช้ port 20 สำหรับข้อมูลทุกกรณีจึงไม่ครบ ต้องบอก active/passive และบริบท ส่วน SFTP เป็นบริการถ่ายโอนผ่าน SSH และ FTPS คือ FTP ที่ใช้ TLS เป็นคนละระบบ

แปลและเรียบเรียงสถาปัตยกรรมเว็บ

Web เป็นบริการบน Internet ที่ใช้ทรัพยากรและการอ้างอิงระหว่างกัน Browser ทำหน้าที่ client เรียกข้อมูลจาก server หน้าเว็บหนึ่งหน้าอาจมี HTML หลักและ objects จำนวนมากจากหลาย server Web จึงไม่เท่ากับ Internet ทั้งระบบ

HTTP กำหนดข้อความ request/response ในบริบท HTTP/1.x ที่สไลด์ใช้ จะอธิบายการขนส่งบน TCP และข้อความเชิงบรรทัด ส่วนหลักการที่ต้องรู้คือ method, path, headers, status และ body ไม่ตีความตัวอย่างยุคต้นฉบับเป็นข้อกำหนดทุกเวอร์ชัน

กลับสารบัญ ↑

รูปข้อความ HTTP/1.x

GET /index.html HTTP/1.1
Host: example.com
Connection: close

Request line ระบุ method, request target และ version จากนั้นเป็น headers บรรทัดว่างคั่นก่อน body ตัวอย่างนี้ไม่มี request body Header Host สำคัญเมื่อหลายเว็บไซต์แชร์ server เดียวกัน Path ไม่ใช่ IP และไม่จำเป็นต้องเป็นชื่อไฟล์จริงในดิสก์

Response มี status line เช่น HTTP/1.1 200 OK ตามด้วย headers และอาจมี body รหัสที่ควรแยกคือ 200 สำเร็จ, 301 ย้ายถาวร, 304 ใช้ cached representation ที่ตรวจเงื่อนไขแล้ว, 400 request มีปัญหา, 404 ไม่พบ, 500 ความผิดพลาดฝั่ง server

Non-persistent, Persistent และเวลา

ในแบบ non-persistent ที่คิดหนึ่ง object ต่อ TCP connection ต้องใช้ประมาณ 1 RTT สร้าง TCP + 1 RTT ส่ง request และรอ response เริ่มต้น + เวลาส่ง object จึงได้ 2RTT+L/R เมื่อไม่คิด DNS และปัจจัยอื่น

ถ้า RTT=80 ms และ object 100 kB บนลิงก์ 10 Mb/s เวลาส่ง=100,000×8/10,000,000=80 ms จึงได้ประมาณ 240 ms สำหรับหนึ่ง object ตามสมมติฐานนี้ Persistent ใช้ connection เดิมซ้ำ ลดการสร้าง connection แต่เวลาทั้งหน้าแปรตามการเรียก object และ concurrency

กลับสารบัญ ↑

State, Cookies และ Cache

HTTP stateless หมายถึงตัว protocol ไม่บังคับให้จำบริบท request เดิมทุกครั้ง แอปยังมี state ได้ด้วย cookie/session Cookie ช่วยส่งค่าที่ server ให้กลับใน request ถัดไป ไม่จำเป็นต้องเก็บรหัสผ่านตรง ๆ และไม่ใช่สิ่งเดียวกับ cache

Cache เก็บ representation เพื่อตอบเร็วและลดโหลด Conditional request เช่น If-Modified-Since หรือ If-None-Match ช่วยตรวจความใหม่ Response 304 ไม่มี representation body ใหม่แบบ 200 ทั่วไป ต้องมีของเดิมที่ cache ใช้ได้

ลองตอบ: 404 แปลว่าไม่มี Internet หรือไม่

เฉลยและเหตุผล: ไม่ 404 เป็น response จากบริการที่ประมวลผล HTTP ได้และบอกว่าไม่พบ resource ตามคำขอ การเชื่อมเครือข่ายกับการมี resource เป็นคนละเรื่อง

ลองตอบ: Stateless ทำ login ไม่ได้หรือไม่

เฉลยและเหตุผล: ทำได้ แอปจัด state โดย token/cookie และข้อมูล session ของตน โปรโตคอล stateless ไม่ได้ห้ามแอปมีความจำ

จำให้ได้: HTTP request/response; เวลาแบบพื้นฐาน 2RTT+ส่งข้อมูล; cookie ≠ cache; 304 ≠ error ข้อมูลหาย

ตัวอย่างอ่าน Counter

Delay, Jitter และ Playout Buffer

Delay คือเวลาตั้งแต่ส่งถึงปลายทางตามนิยามที่วัด ส่วน Jitter คือความแปรปรวน packet delay Playout buffer หน่วงการเล่นเล็กน้อยเพื่อรองรับการมาถึงไม่สม่ำเสมอ เพิ่ม buffer มากช่วยลดการเล่นสะดุดบางกรณี แต่เพิ่ม latency และไม่แก้ bandwidth ขาดระยะยาว

ตัวอย่างส่งเสียงทุก 20 ms แต่การมาถึงมี delay 50,60,95,55 ms ถ้าเริ่มเล่นหลังส่ง 70 ms packet ที่ delay 95 ms จะมาช้าเกินจุดเล่น แม้ค่าเฉลี่ยยังต่ำกว่า 70 จึงต้องมองการกระจายและการชดเชย ไม่ดูค่าเฉลี่ยอย่างเดียว

RTP, RTCP และ Signaling

RTP มี sequence number, timestamp และข้อมูลระบุ payload ช่วยจัดลำดับและจังหวะสื่อ แต่ไม่รับประกัน bandwidth หรือไม่สูญหาย RTCP รายงานและประสานข้อมูลควบคุมที่เกี่ยวข้อง ส่วนการตั้ง/ยุติ session เช่น SIP เป็นหน้าที่ signaling อีกส่วน ไม่ใช่ตัว RTP

Sequence number ช่วยสังเกตการขาดหรือผิดลำดับ Timestamp ใช้สัมพันธ์เวลาสื่อ ไม่ได้แปลว่าตรงกับนาฬิกาบอกเวลาของมนุษย์โดยตรง ต้องทราบ clock rate ของชนิดสื่อ

ลองตอบ: เพิ่ม buffer ทำให้คุยสดดีขึ้นเสมอหรือไม่

Symmetric cryptography ใช้กุญแจลับร่วมกันเพื่อเข้ารหัส/ถอดรหัสตามระบบ ส่วน Asymmetric cryptography ใช้คู่ public/private key ที่มีความสัมพันธ์ทางคณิตศาสตร์ ผู้รับเผย public key ได้แต่เก็บ private key เป็นความลับ บริบทของการใช้กุญแจขึ้นกับว่างานเข้ารหัสหรือเซ็น

Hash, MAC และ Digital Signature

Hash สร้าง digest โดยไม่ใช้กุญแจลับในนิยามพื้นฐาน หากส่งข้อความกับ hash ผ่านช่องที่ผู้โจมตีแก้ได้ทั้งคู่ ผู้โจมตีอาจคำนวณ hash ใหม่ จึงยังไม่ยืนยันผู้ส่ง

Message Authentication Code ใช้กุญแจลับร่วมกันช่วยตรวจ integrity และยืนยันว่ามาจากผู้รู้กุญแจ ส่วน Digital Signature ใช้ private key เซ็นและ public key ตรวจตาม scheme ช่วยให้ตรวจหลักฐานโดยผู้ที่ไม่มีกุญแจเซ็นได้ ลายเซ็นไม่ทำให้เนื้อหาลับโดยอัตโนมัติ

IPsec

Security Association หรือ SA เป็นบริบทการรักษาความปลอดภัยของทิศทางหนึ่ง มีข้อมูลเช่นตัวระบุและกุญแจตามระบบ การส่งสองทิศจึงต้องมีบริบทที่เหมาะสมทั้งสองทาง AH เน้น integrity/authentication ของส่วนที่ออกแบบให้คุ้มครอง ส่วน ESP ให้การปกป้อง payload รวมถึง confidentiality เมื่อใช้ encryption ที่กำหนด

TLS และ HTTPS

TLS handshake เจรจาพารามิเตอร์ ยืนยันตามวิธีที่ใช้ และสร้างบริบทกุญแจสำหรับ application data HTTPS คือ HTTP บนการปกป้องด้วย TLS ตามการใช้งานนั้น Browser ต้องตรวจ certificate ของชื่อปลายทางด้วย ไม่ใช่แค่เห็นกุญแจแล้วรับทุกตัวตน

TLS ป้องกันข้อมูลระหว่าง endpoints ของช่อง ถ้า endpoint ถูกยึด ข้อมูลก่อนเข้ารหัส/หลังถอดยังเสี่ยง และการป้องกันช่องไม่ได้ยืนยันว่าเนื้อหาจากคู่สื่อสารถูกต้องทุกข้อความ

VPN และ Firewall

Packet-filter firewall ดู fields เช่น IP, protocol และ port; Stateful firewall ติดตามสถานะการสื่อสาร; Application proxy ตรวจในระดับบริการได้ลึกขึ้นตามระบบ Default policy และลำดับ rule สำคัญ เพราะกฎที่ตรงก่อนอาจกำหนดผลต่างกัน

PGP

PGP รวมกลไกเช่น hash/signature, compression, symmetric encryption และ public-key mechanism เพื่อปกป้องข้อความตามรูปแบบ การเซ็นกับการเข้ารหัสอาจทำร่วมกันแต่ต้องรู้ว่าแต่ละขั้นให้คุณสมบัติอะไร ไม่ตอบว่า “ใช้ public key จึงมีทุกคุณสมบัติ”

จำให้ได้: รู้ว่า rdt แต่ละรุ่นเพิ่มกลไกเพื่อแก้สมมติฐานใด; ทำโจทย์ TCP ให้นับ byte และเขียนเหตุการณ์

จาก Forwarding Table ไปยังการเดินทางจริง

เมื่อ router รับ frame จะตรวจข้อมูลที่จำเป็น ถอดส่วนชั้นลิงก์ แล้วใช้ destination IP หาเส้นใน forwarding table ต่อไปสร้าง frame สำหรับลิงก์ขาออก ฝั่งขาเข้าและขาออกอาจเป็นเทคโนโลยีต่างกัน ไม่จำเป็นต้องเป็น Ethernet ตลอด

ส่วนประกอบ router ที่สไลด์ใช้คือ input ports, switching fabric, output ports และ routing processor Queue เกิดได้ทั้งขาเข้าและขาออกตามข้อจำกัด Head-of-line blocking คือ packet หัวคิวกีดขวาง packet หลังแม้หลังจะไป output ที่ว่างได้

Subnet ไม่ใช่จำนวนเครื่องที่ต่อ switch เท่านั้น

Subnet เป็นกลุ่ม interface ที่สื่อสารถึงกันในลิงก์/โครงสร้างที่ออกแบบโดยไม่ผ่าน router สำหรับ subnet นั้น Router มีหลาย interface จึงอยู่หลาย subnet ได้ และการนับ subnet ในรูปต้องดูแต่ละ LAN รวมถึงลิงก์ระหว่าง router ตาม IP ที่กำหนด

IP address ผูกกับ interface เป็นหลัก เครื่องเดียวหลาย interface อาจมีหลาย address ไม่ใช่หนึ่งเครื่องต้องมี IPv4 เพียงหนึ่งเลขตลอดไป การคิด subnet ให้เริ่มจาก prefix และขอบเขตลิงก์

DHCP, NAT และ IPv6 เชื่อมอย่างไร

เครื่องได้ค่า IP/mask/gateway/DNS จาก DHCP ก่อนจึงใช้ subnet decision และ routing ตามปกติ หากผ่าน NAT ที่ทางออก mapping อาจแปล source IP/port เป็นภายนอก ส่วน DNS เป็นการค้นชื่อ ไม่ได้เป็นตัวแจก address ให้ interface แทน DHCP

IPv6 แก้ขนาด address และโครงสร้างบางส่วน แต่การเปลี่ยนผ่านต้องรองรับเครือข่ายหลายแบบ อ่านบท 19–21 เพื่อแยก address format, datagram และ protocol ควบคุม

Routing ตามลำดับการคิด

  1. แปลงโจทย์เป็น graph ที่มี node, edge และ cost ให้ตรงภาพ
  2. ระบุว่าใช้ link-state หรือ distance-vector และรู้อะไรบ้างตอนเริ่ม
  3. คำนวณแต่ละรอบพร้อม predecessor หรือ next hop ไม่บันทึกแค่ cost สุดท้าย
  4. นำเส้นทางที่ได้ไปสร้าง forwarding table ที่ต้นทางนั้น
  5. ถ้าข้าม AS ให้พิจารณานโยบายและ attributes ตามที่กำหนด ไม่ใช้ Dijkstra แทน BGP โดยอัตโนมัติ

Multicast กับ Tree

Shortest-path tree จาก source อาจต่างจาก shared tree ที่ลดโครงสร้างรวม บางต้นไม้เหมาะต่อระยะทางแต่ไม่ใช่ต้นทุนรวมต่ำสุด Steiner tree เป็นโจทย์ต้นทุนรวมที่ต่างจากการหา shortest path ถึงแต่ละคน

PIM sparse mode ใช้แนวรวมกลุ่มผ่านจุดที่กำหนดในแบบที่สไลด์อธิบาย ส่วน dense mode เริ่มจากแนวกระจายกว้างแล้วตัดสาขา ความแตกต่างนี้ดูความกระจายของสมาชิก ไม่ใช่ดูจำนวนบิตใน multicast address

ลองตอบ: Router มี 3 interfaces ต้องมี IP เดียวหรือไม่

เฉลยและเหตุผล: ไม่ โดยทั่วไปแต่ละ interface IP ต้องมี address ที่สัมพันธ์ subnet ของตนตามการตั้งค่า และอาจมีหลาย address ได้ตามระบบ

ลองตอบ: ได้ route cost แล้วตอบ next hop อย่างไร

เฉลยและเหตุผล: ย้อน predecessor จากปลายทางกลับต้นทาง แล้วหยิบโหนดถัดจากต้นทาง ไม่ใช่ใส่ปลายทางทุกบรรทัดเป็น next hop

บริการ Link Layer ที่ไม่เหมือนกันทุกเทคโนโลยี

Link layer ห่อ datagram เป็น frame บนลิงก์ มีการเข้าถึงช่องและตรวจข้อผิดพลาดตามระบบ บางเทคโนโลยีมี reliable delivery/flow control เพิ่ม บางแบบไม่ให้ จึงไม่ยกบริการหนึ่งไปเหมารวมทุก link

Adaptor/NIC จัดการส่วน link และ physical จำนวนมากร่วมกับ driver/OS ที่เครื่องปลายทาง ภาพ logical layer ไม่ได้แปลว่าทั้งชั้นเป็นโปรแกรมใน CPU อย่างเดียว

กลับสารบัญ ↑

ARP และ MAC ตามแต่ละ Hop

สมมติ A อยู่ LAN1 ส่งให้ B อยู่ LAN2 ผ่าน R: IP ต้นทาง A และ IP ปลายทาง B ใส่ใน datagram; frame แรกมี MAC A→MAC R ขาฝั่ง LAN1; R ส่ง frame ใหม่เป็น MAC R ขาฝั่ง LAN2→MAC B ในกรณีพื้นฐาน IP คู่เดิมยังคงอยู่

หาก LAN2 มี switch สวิตช์ไม่เปลี่ยน IP และไม่จำเป็นต้องเปลี่ยน source/destination MAC เพียงเพราะ frame ผ่านพอร์ต มันเลือกขาออกตามตาราง MAC ของ VLAN นั้น

กลับสารบัญ ↑

Error Detection และ MAC Protocols

Parity, checksum และ CRC เพิ่ม redundancy เพื่อช่วยตรวจผิดตามความสามารถโค้ด ไม่รับรอง authenticity ทบทวนบท 10 ส่วนการแบ่งช่อง TDMA/FDMA, ALOHA และ CSMA ดูบท 12 โดยผูกกับสมมติฐานของสื่อร่วม

โจทย์ ALOHA ที่ถาม 1/e หรือ 1/(2e) เป็นประสิทธิภาพสูงสุดในแบบจำลองเฉพาะ ไม่ใช่คำตอบประสิทธิภาพ Ethernet หรือ Wi-Fi ทุกระบบ และ Ethernet full-duplex ที่ต่อ switch ไม่ใช้การชนแบบ hub

กลับสารบัญ ↑

VLAN และ MPLS

VLAN แบ่ง broadcast domain เชิงตรรกะบน LAN ส่วน MPLS ส่งต่อตาม label บนเส้นทางที่สร้างไว้ มีตาราง incoming label → outgoing label/interface ค่า label มีความหมายตามบริบท ไม่จำเป็นต้องคงเลขตลอดเส้นทาง

Label switching ไม่ได้แปลว่า “ลืม IP ทั้งระบบ” เพราะ IP routing/control plane ยังเกี่ยวข้องในการสร้างเส้นทางตามระบบ และการเลือกเส้น MPLS อาจมีเงื่อนไข traffic engineering แตกต่างจาก shortest IP route ปกติ

Data Center Networks

Data center มีเครื่องจำนวนมาก เชื่อมผ่าน rack switches และชั้นเครือข่ายอื่น เน้นความจุระหว่างเครื่องและเส้นทางหลายทาง Load balancer ในรูปทำหน้าที่กระจายงานไปบริการปลายทางต่างจากการ switch frame อย่างเดียว จุดคอขวดอาจเป็น uplink แม้ทุกเครื่องมี NIC เร็ว

สังเคราะห์: ตั้งแต่ต่อโน้ตบุ๊กจนเปิดเว็บ

  1. เชื่อมลิงก์กายภาพ/ไร้สายให้ได้ก่อน เช่น Ethernet link หรือ Wi-Fi association
  2. ได้ IP, mask, gateway, DNS เช่นผ่าน DHCP โดยตรวจค่าที่ได้
  3. แยกชื่อ host จาก URL และถาม DNS หากไม่มีข้อมูลใน cache
  4. ถ้า DNS หรือเว็บอยู่นอก subnet ให้หา next hop ผ่าน routing แล้ว ARP หา MAC ของ gateway ในกรณี IPv4/Ethernet
  5. ส่ง frame ผ่าน switch ไป router; router เลือกเส้นตาม IP และเปลี่ยนกรอบลิงก์ตามขาออก
  6. ตั้ง transport ที่แอปต้องใช้ เช่น TCP handshake ในตัวอย่าง HTTP/1.x และ TLS เพิ่มสำหรับ HTTPS ตามระบบ
  7. ส่ง HTTP request รับ response และเรียก objects เพิ่มตามหน้าเว็บ; ใช้ buffer, ACK, retransmission ตาม protocol ที่เกี่ยวข้อง
  8. แยกอาการเมื่อเสีย: link, address, gateway, DNS, transport, TLS และ application ต้องตรวจต่างจุด

ลองตอบ: VLAN กับ MPLS ทำสิ่งเดียวกันหรือไม่

เฉลยและเหตุผล: ไม่ VLAN แบ่งโดเมนชั้น 2 ส่วน MPLS ใช้ label ในการส่งต่อตามโครงข่ายและเส้นทางที่กำหนด แม้ทั้งคู่มีการใส่ข้อมูลกำกับเพิ่มเติม

  5. หากเป็น subnet IPv4 ปกติถึง /30 ช่วง host คือ network+1 ถึง broadcast−1 และจำนวน host=2^h−2

5.2.2.2 — Router แบ่ง Broadcast Domains

คำแปลเรียบเรียง · อธิบายเสริม · สรุป · คำถามพร้อมเฉลย

อ่านเทียบไฟล์: 5.2.2.2 Packet Tracer - Routers Segment Broadcast Domains.pka

แปลชื่อและเป้าหมายติว

Routers Segment Broadcast Domains = เราเตอร์แบ่งขอบเขตการกระจาย broadcast กิจกรรมหัวข้อนี้ให้สังเกตว่า Ethernet broadcast แพร่ใน LAN/VLAN เดียวกันได้ แต่ router ไม่ส่งต่อ Layer 2 broadcast ไปทุก interface ตามปกติ

กลับสารบัญ ↑

ทำความเข้าใจจากสถานการณ์สมมติ

ถ้า PC A กับ B ต่อ switch ฝั่งซ้าย และ PC C ต่อ switch อีกฝั่งของ router จะมี broadcast domains อย่างน้อยสองส่วนตาม subnet/VLAN ที่กำหนดในรูปจริง การเพิ่ม switch ใน LAN เดียวกันไม่ได้เพิ่ม broadcast domain โดยอัตโนมัติ ส่วนการแบ่ง VLAN เพิ่มโดเมนได้แม้ switch ตัวเดียว

กลับสารบัญ ↑

ขั้นทดลอง

  1. เปิดไฟล์และวาดขอบเขตแต่ละ LAN/interface ของ router จาก topology จริง
  2. ดู IP/mask ของ PC เพื่อรู้ว่า destination ที่ทดสอบเป็น local หรือ remote
  3. เลือก Simulation แล้วกรอง ARP/ICMP ตามที่ต้องสังเกต ล้างรายการ event เดิมหากต้องการเริ่มรอบใหม่
  4. ส่ง ping หรือ Simple PDU ภายใน LAN และดู ARP request แบบ broadcast เมื่อยังไม่มี cache
  5. ทดสอบข้าม router ดูว่า PC ต้นทาง ARP หา gateway ไม่ใช่ MAC ปลายทางอีก LAN
  6. จดว่า broadcast หยุดที่ไหน และ router สร้าง frame ใหม่ออก interface ใด
กลับสารบัญ ↑

ผลที่ควรอธิบายได้

ARP broadcast ของ LAN หนึ่งไม่กลายเป็น Ethernet broadcast ข้าม router โดยทั่วไป แต่การ ping แบบ unicast ข้าม subnet ทำได้หาก addressing/routing ถูกต้อง Broadcast ไม่ข้ามไม่ได้แปลว่าเครื่องต่าง LAN คุยกันไม่ได้

ลองตอบ: นับ broadcast domain จากจำนวนพอร์ต switch ได้เลยหรือไม่

เฉลยและเหตุผล: ไม่ ต้องดู VLAN และส่วนที่ถูก router แบ่งออก แต่ละพอร์ตไม่เท่ากับ broadcast domain หนึ่งอันเสมอ

จำให้ได้: แยก collision domain กับ broadcast domain แล้วชี้ขอบเขตจากรูปจริง

5.4.3.2 — สังเกต Dynamic Routing Updates

คำแปลเรียบเรียง · อธิบายเสริม · สรุป · คำถามพร้อมเฉลย

อ่านเทียบไฟล์: 5.4.3.2 Packet Tracer - Observing Dynamic Routing Protocol Updates.pka

แปลชื่อและเป้าหมายติว

Observing Dynamic Routing Protocol Updates = สังเกตข้อความอัปเดตของโปรโตคอล routing แบบไดนามิก จุดที่ต้องเรียนคือ route ถูกเรียนจากเพื่อนอย่างไรและเปลี่ยนหลัง topology เปลี่ยนอย่างไร ไม่ใช่ใส่ static route ให้ผ่านแล้วจบ

กลับสารบัญ ↑

ขั้นทดลอง

  1. อ่านโจทย์ว่าใช้ protocol ใด แล้วตรวจ configuration จริง ห้ามสมมติว่าเป็น RIP เพียงเพราะเป็นแบบฝึกพื้นฐาน
  2. ใช้ show ip protocols หากอุปกรณ์รองรับ และ show ip route เพื่อบันทึก protocol, prefix และ next hop
  3. Simulation เลือก event ของ protocol ที่กิจกรรมใช้ แยก periodic update, request, advertisement หรือข้อความอื่นตามที่เห็น
  4. สังเกตว่าข้อมูลที่แลกเป็น distance/route หรือ topology แล้วเชื่อมกับ DV/LS ตาม protocol
  5. หากโจทย์ให้เปลี่ยนลิงก์ ให้ทำบนสำเนาและดูช่วงที่ route ยังไม่คงที่ (convergence)
  6. ทดสอบ packet ระหว่าง convergence และหลังนิ่ง เปรียบเทียบเส้นทางกับ reachability
กลับสารบัญ ↑

จุดวิเคราะห์

Static route เป็นค่าที่กำหนดเอง ไม่ได้กระจายเป็น dynamic update โดยอัตโนมัติทุกระบบ ส่วน convergence มีเวลาและกติกา ไม่ใช่สายเปลี่ยนแล้วทุก router รู้ทันที หากมีเส้นทางสำรองต้องดู cost และ policy ที่ใช้

ลองตอบ: Dynamic route เปลี่ยนทันทีทุก router พร้อมกันหรือไม่

เฉลยและเหตุผล: ไม่ ขึ้นกับการตรวจเหตุการณ์ การส่งข่าว การคำนวณ และกลไก protocol จึงมีช่วง convergence

จำให้ได้: รู้ protocol จริงก่อนตีความ event และเปรียบเทียบตารางก่อน/หลังด้วย prefix เดียวกัน

TXD/RXD ใช้ส่งและรับข้อมูล RTS/CTS ใช้ควบคุมตามการจับมือที่อุปกรณ์รองรับ DTR/DSR แสดงความพร้อมตามหน้าที่ที่กำหนด และ Signal ground เป็นจุดอ้างอิง ตัวขั้วต่อจำนวนขาและระดับแรงดันต้องอิงมาตรฐาน/อุปกรณ์จริง ไม่เอาสัญญาณ TTL มาเสียบตรงโดยเห็นว่าเป็น serial เหมือนกัน

USB

USB เป็นบัสอนุกรมที่มี host ควบคุมการใช้งานตามโครงสร้างของระบบ รองรับอุปกรณ์หลายประเภทและการเชื่อมผ่าน hub รูปแบบ transfer ที่ควรแยกคือ Control สำหรับจัดการ, Bulk สำหรับข้อมูลจำนวนมากที่เน้นความถูกต้อง, Interrupt สำหรับการตรวจรับข้อมูลตามช่วงที่กำหนด และ Isochronous สำหรับข้อมูลที่ให้ความสำคัญกับจังหวะ

ชื่อ Interrupt transfer ไม่ได้แปลว่าอุปกรณ์แย่งเส้นลวดส่งเข้า CPU เองนอกระบบ host scheduling และ Isochronous ไม่ได้สัญญาว่าข้อมูลผิดทุกบิตจะถูกส่งซ้ำทันเส้นตาย ความต้องการเวลาและความถูกต้องมีข้อแลกเปลี่ยน

ชนิดหัวต่อ เช่น Type-A/Type-B/Type-C เป็นเรื่อง connector ส่วนหมายเลขรุ่น USB เป็นเรื่องความสามารถมาตรฐาน ไม่ควรเห็นหัวต่อแล้วสรุปอัตราส่งจากรูปร่างอย่างเดียว

FireWire

FireWire หรือ IEEE 1394 เป็นตัวอย่างอินเตอร์เฟสอนุกรมความเร็วสูงในเอกสาร เน้นรองรับการส่งข้อมูลและงานสื่อด้วยกลไกที่ต่างจาก USB สไลด์เก่าอาจให้ตัวเลข 400/800 Mb/s ตามรุ่นที่ยก ต้องใช้ค่าโจทย์และอย่านำไปเทียบกับ USB ทั้งตระกูลโดยไม่ระบุรุ่น
